## 1. 密钥性质与实际访问者

当前候选是 **NAS 文件中的 Ed25519 软件密钥，非 HSM/KMS，不具备不可导出保证**。目标路径为 `SIGNER_STORE_DIR/ed25519.pkcs8`（PKCS8 DER、0600）；目录0700。NAS 本地挂载点可为 `/mnt/nas`，但配置的存储目录须是其子目录，例如 `/mnt/nas/ltzzz-signer`。私钥只在目标云运行时生成/使用；GPT 的 CI 不应接收私钥，但软件文件和云管理员权限本身不能证明其不可读取。

POSIX 0600 不等于 IAM 隔离：能挂载该 NAS、取得同一 UID/root 权限，或修改函数代码/启动命令以访问目录的主体，都可能取走文件。身份清单必须覆盖直接读者和能间接取得读取能力的发布/调试主体。

|---|---|---|
| 火山账号 | 受管 GetFunction 回读账号 `2131926778`、北京、函数 `jt247vfx` | 账号标识已核对；账号下具体 IAM 用户/角色及管理员权限未盘点 |
| 函数运行身份 | 候选要求真实 NFS/NFS4、受限目录/文件权限 | UID/GID、函数绑定角色、挂载权限、实际文件属主均未验证 |
| NAS 管理与可挂载主体 | 桌面回执报告文件系统/VPC/挂载点已创建，挂载保存仍受工单限制 | NAS 权限组、网段授权、其他可挂载资源及特权主体未回读 |
| 云发布/调试/运维主体 | 豆包桌面执行端报告控制台操作；报告不等于云 IAM 身份证明 | 真实主体 ID、策略、可更新函数/启动命令/挂载的权限均未核验 |

| GPT/Claude/千问等逻辑席位 | 名称与聊天身份不是云权限边界 | 本身不证明能读或不能读；按真实执行器及云身份逐项登记 |

以上未知项就是待补的读取权限清单，**不能登记成“无其他读者”或“已隔离”**。生产登记前由已登记云维护执行器从官方控制面回读：主体 ID/角色、有效策略与继承、函数发布/调试权限、NAS 权限组/挂载资源/UID/GID、密钥文件权限；仅保存非敏感身份/策略引用、哈希、时间与 request ID。若不能完整枚举，保持 `reader_inventory_verified=false`，不得宣称云私钥不可导出。不得通过下载私钥来证明“可读”。

## 2. 崩溃遗留锁的恢复职责

`.transaction-lock` 是 NFS 目录锁，**无超时、无自动抢锁**。异常退出可能遗留锁并导致后续签名失败。这是已知的可用性代价；本次不改变运行时锁逻辑，不允许因锁“很旧”就删除。

责任主体是原任务登记的 **火山云维护执行器**，需同时具备可核验的函数运维和目标 NAS 维护权限，并使用现有任务认领/租约排他执行。当前逻辑接力席是豆包桌面执行端，真实云主体尚待上述清单绑定；GPT/千问负责协调与证据复核，不能凭席位名称操作 NAS。未绑定实际维护主体时记 `blocked_maintenance_principal_unverified`。恢复不新增 owner 逐次审批门，也不改原有预算/签名要求。

清锁必须按以下顺序留痕；任何一步失败就保持关闭和原锁：

1. 沿用原 Task ID 建恢复步骤/认领，记录服务、存储、源码、锁状态和时间；先与已有恢复记录对账，避免两个维护端并行清理。
2. 冻结新 `/attest` 和 `/challenge` 请求，`NATIVE_ATTESTATION_ENABLED=false`；核对全部仍可接流量的 revision、实例与在途请求已停止/排空。仅新发一个版本、仅关一个路由或仅看锁 mtime，均不足以证明旧持锁进程退出。至少两次控制面快照覆盖真实最大请求时限，并保存关闭入口及无活跃持锁执行的证据。
3. 在云内核对真实 NFS/NFS4 挂载、存储目录、文件属主/权限；保存锁目录元数据、账本原字节备份/哈希与已有公钥标识，不读取或导出私钥。坏账本/坏密钥保持失败，不重置预算、不重新生成密钥。
4. 逐项对账账本里的进行中/未知操作与已有原生 response/request ID、签名与交付回执。未知结果继续保持预留；没有查清不能重试付费调用或删账本。
5. 只有排他维护认领、停止/排空、存储身份和对账证据都齐全，才删除核对过的**空** `.transaction-lock` 目录（rmdir 语义）。不递归删目录，不删 ledger，不改预算，不复制或替换 key。清锁前后记录目录状态及运维 request/run ID；目录非空、观察变化或证据不足就停止。
6. 保持业务签名关闭，完成真实 NFS 并发互斥演练；用全新 nonce 做受管认证挑战并验签。验收须同时看到不同 `instance_boot_id`、同一公钥/指纹、正确签名及绑定源码/账号；旧 `/health` 的 `key_persisted=true` 不算证明。部署与重启可验证后，仍按原阶段审计要求决定受控验收，不据清锁成功启用 A2、资金或信任登记。

恢复回执至少记录：原 Task ID、维护主体/认领、环境与 revision/源码绑定、停止入口与两次排空证据、锁目录操作前后、账本备份哈希与逐项对账、原/后公钥指纹、不同启动标识与新 nonce 验签、未决项、是否实际清锁。私钥、认证头和模型凭据不入回执。没有实际操作就写 `performed=false`；文档不是清锁完成证明。

## 3. 部署前仍需取得的证据

- 身份/读取权限清单与真实持久 NAS 挂载；控制台保存网络配置不等于挂载生效。
- 精确已审源码、发布版本与运行时源码闭包核对；不得只改环境变量中的源码哈希来掩盖不一致。
- 真实 NFS 并发锁演练、实际重启同公钥的新 nonce 签名，以及同服务内一次真实原生豆包响应与签名；本地合成测试不抵扣这些验收。
- `/health` 在候选中不访问 NAS、不建钥、不调用模型，返回200只证明入口可用。桌面报告的旧 `/tmp` 响应不能抵扣持久化证明。
- 信任登记、签名准入和 A2 等按各自原阶段验收；本修订不执行部署/登记/启用，也不恢复付费定时任务。
