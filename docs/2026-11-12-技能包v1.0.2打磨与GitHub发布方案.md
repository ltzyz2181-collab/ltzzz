## 一、已落地的打磨（v1.0.1 → v1.0.2）

### 1. SKILL.md（16 行正文 → 8 条流程 + 边界段，38 行）

| 改动 | 内容 | 对应短板 |
|---|---|---|
| 开工三确认 | 核对范围、来源清单（含是否允许联网）、交付形式 | 原正文只有“先确认核对范围”，范围与授权边界含糊 |
| 拆事实编号 | 拆成最小事实单元并连续编号；观点/预测/承诺单列 | 原为“拆成可核对的事实”，未要求编号，长文无法对账 |
| 来源分层 | 原始来源优先（官网/公告/文书原文/合同），二手转述标“二手”；未打开链接不算核验 | 原只有“未打开的链接不能写成已核验”，未区分一手/二手 |
| 口径统一 | 十进制/二进制、含税/不含税、累计/当期、单体/合并，先统一再比 | 上一轮实测暴露“约100→120”“2000GB→2TB”两处无口径可依 |
| 四档 + 限定标签 | 判断后必挂时点/主体/范围/数量/单位/程度/条件，命中哪项写哪项 | 报告点名的第一短板：缺限定标签 |
| 资料属性 | 每条标“资料自述”或“独立核实”，只有读到外部原始来源才算独立核实 | 原仅在第 5 条含糊提及“区分资料自述和独立核实” |
| 冲突并列 | 两源矛盾时并列原文与适用条件，不擅自择一 | 原模板有冲突区块但正文无判定规则 |
| 长文分批 | 超 20 条事实按章节分批，逐批连续编号，末尾给统计与一句话结论 | 原无分批规则，长文必然漏项 |
| 边界段 | 不替代鉴证/审计/法律意见；未读取内容一律标未核验；不用“应该”补圆 | 原仅一句“不替代专业鉴证”，未覆盖“用常识补圆”这一失效模式 |

### 2. templates/report.md（6 列 → 7 列 + 5 个区块）

- 列：编号 / 原说法 / 判断（含限定标签）/ **资料属性** / 实际来源及位置 / 必要摘录 / 修订建议或缺项。
- 新增区块：**输入与范围**（稿件路径、读取时间、核对范围与排除项、来源清单、是否允许联网）、**未核实项表**（原因分类 + 补齐方式）、**资料冲突及适用条件表**（A/B 原文与时间、冲突点、适用条件）、**统计与结论**（四档计数 + 一句结论 + 修订优先级）、**边界声明**。
- 说明：“输入元信息”落在表格上方的区块，不单列成列，避免表头过宽；实际列数是 7 不是 8。

### 3. references/examples.md（2 条 → 13 条判例）

覆盖：已提交被写成已发布/已取得收入、资料没提某功能、时点错配（拟申报→已获得）、口径偏移（累计签约→服务客户）、主体错位（注册地址→总部）、单位换算（十进制/二进制）、范围越界（六省→全国）、数量含外包、程度夸大（内部测算→显著提升）、预测当事实、二手转述、链接未打开、双源冲突。每条给“说法→资料实况→判断（含标签）→口径要点”，末尾附通用口径 4 条。

### 发布前门槛（四条全过才做）

2. `tests/validate-examples.mjs` 在独立仓可跑通，`validate.yml` 绿。
3. 脱敏清单逐项签核：无客户数据、无内部路径/邮箱/令牌、无未公开报价、作者主体已在平台公示。
4. 许可证与署名口径已拍板（见裁决 C）。

### 许可证三选一（需 GPT 裁）

- Apache-2.0：允许商用与修改，需保留版权与变更说明。适合“想被更多人用、想被集成”。
- CC BY-NC 4.0：非商业可用。适合“公开示范、保留商业服务空间”（本包商业模式是服务费，不是软件授权）。
- 保留所有权利（All rights reserved）：仅公开可读，禁止再分发。适合“只做展示与背书”。

本席倾向 **CC BY-NC 4.0**：与“技能免费、卖核对服务”的商业模式一致，且不鼓励别人拿去做付费工具。
