# 评审接管内部人工审批

类型：事实与当前实施状态。Owner 2026-10-21 最新决定，优先于旧稿中的逐次人工确认要求。

权限唯一源为 `config/autonomy-authority.json`，本次审批规则为 `config/review-delegation.json`。GPT 总控和千问代行总控继续执行、合并、部署和修复；评审负责监督、提醒、验收和留下异议，没有任免席位、收回凭证或削减总控权限的接口。拒收必须附理由，转修订和复核，不转为“等老板批准”。总控有异议时保留指挥权，记录处理理由，不能把评审拒绝篡改为通过。

## 回执格式与信任边界

素材填 `review_reference: {path, sha256}`；记忆候选同名字段。引用 `knowledge/results/` 或 `results/` 中执行器保存的完整回执，不直接接受模型自述或 `accepted:true` 复选框。

回执包括 Actions `run_id`、40 位来源提交、两个不同**实际供应方**的完整调用结束记录，以及 worker/reviewer 工件正文和 SHA-256。Worker 工件包含 `operation`、`subject`、`subject_sha256`；reviewer 工件包含同一操作和主题哈希、`artifact_sha256`、`accepted`、`reasons`。只有三者逐字一致才可消费。GPT/OpenAI、Claude/Anthropic、豆包/Ark 等供应方别名会归一化，不能换名字自审。

这是可信仓库执行器保存的回执校验，不是供应商签名的密码学证明；有仓库任意写权限的人仍可伪造文件，因此凭证不交给模型，模型正文不能覆盖外层运行记录。无凭证 JSON 投票仍只用于影子研究，绝不用于支出。

既有 ANS 工程验收与附加记忆评审**分别给结论**。工程通过不能自动晋升一条记忆；已有模型调用结束不完整、同供应方审核、来源改变、候选冲突或缺少附加结论时，记录真实失败原因。后续 ANS 周期处理下一条，没有额外模型重试。

派生长期记忆写成功后才更新队列 applied 索引。扫描器不会把“已评审”直接写成“已发布”，也不会把内部积分写成 USDC。线上首次真实附加记忆评审与自动晋升，需以后续实际运行回执验收；本次测试夹具不算真实模型调用。
