# 视频只保留发布记录

owner 在 2026-10-29 明确要求：发布过的视频不再保留成片，油管保留视频，仓库保留小体积发布记录。

同一视频的实际 SHA256 必须与 LTZZZ 频道 `UCnKqseQ7uivSc7FN38ccRUA` 的成功回执一致；视频 ID、`public`、`processed` 和 `published=true` 必须同时匹配。上传成功、拿到 ID、私密、处理中和失败都不能当作已发布。

- `scripts/prune-published-videos.mjs` 只删除 `videos/` 中受 Git 跟踪、实际内容哈希匹配上述证据的 MP4；保留原始成功/失败回执、链接、哈希、清理清单、脚本和字幕。未发布、不确定、非跟踪文件及符号链接保留。
- 原有 `youtube-daily-publish.yml` 在发布步骤后执行清理并提交删除记录，不新建定时任务。发布失败不会删除该失败视频，也不会再次渲染或上传旧视频。运行器制品只存 JSON 回执，不再附带成片。
- 队列先保存已核验的发布回执，再保存 `published/<name>.meta.json`，最后删除队列及 `published/` 下的 MP4。删除失败可沿原回执重试，不会第二次上传。哈希回执是防重依据，必须保留。
- 旧 R2 `published/` MP4 由现有身份调用 `/queue/prune-published` 分页清理；只处理有成功回执、实际字节哈希匹配，且重新查询油管仍为同一公开已处理视频的对象。不删除未知文件、待发布队列或原始转换输入。
- 已清理的当天 Instagram 包重跑时直接跳过，不重新渲染，也不继续使用已移除的 MP4 下载地址。以后需要跨平台使用该视频时沿原发布记录安排，不在本流程自动恢复本地备份。

Git 删除减小当前检出目录和 Pages 制品；已有 Git 历史保留，不强推改写历史，也不声称历史仓库磁盘已经缩小。历史本机工作目录、旧 Actions 制品与平台内视频不因这次提交自动全部消失。
