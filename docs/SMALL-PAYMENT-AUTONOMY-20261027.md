## 自主范围与不变的额度

单笔与同一收款地址＋用途组滚动 24h 合计都严格 <20 Base USDC，6 位整数精度；地址别名与不同控制席合并计数。日/周共享同一个已登记预算。每维基础额度取 `min(登记额度, owner 绝对上限, 2×独立已核额度)`；2×是额外天花板，不是新增预算。保留已有更窄的外部雇佣/投资授权，不复活旧20/60规则。`owner_absolute_*` 是既有数值边界，不是 owner 签名或逐笔审批。

控制权、经济主体、地址和用途须真实核实登记；同 operator 或控制自己的收款方不得豁免。新收款地址、用途、预算/控制字段变更改变 policy 摘要，不能沿用旧签名。原有先预留、跨 worker 串行事务、alarm 确认、一次性执行 permit、未知结果永不自动重试、余额/账实独立验证继续保留。

## 双原生签名与公开冷却

`small-payment-authorization.mjs` 只验公钥，不生成/接触生产私钥，不调用模型或登记新根。千问 `aliyun_dashscope` 和豆包 `volcengine_ark` 必须通过不同已登记云执行器，对完全相同的 policy、release、authority、lifecycle command 摘要签名，角色为 `payment_policy_review`。核对真实 provider/model/request_id、完整 stop 响应、结构化 approve、输出哈希、执行器源码与云部署绑定；有效期最多 24h。模型自述、配置 verified 布尔值、共享 GitHub 账号或 Claude PR 都不算密码学批准。

这里的“原生签名”是独立登记云执行器对自己取得的真实原生响应签名，不是声称模型 API 自带签名，也不是让模型编写签名字符串。Claude 是咨询审计与规划，不参与机器法定人数。

初次激活、每次升级和解冻都先事务预留，再向固定仓库公开完整公钥签名证据与命令，按不可变 40 位提交回读原字节一致，之后再等至少 24h。公开路径固定为 `knowledge/results/payments/activation/<record_sha256>.json`。记录本身不包含自己的整体字节摘要；canonical JSON 的 record 摘要和含 LF 文件的字节摘要分别验证。发布失败保持关闭，保留原预留供同命令恢复；并发重复不能缩短冷却或换成另一条记录。

**24h 冷却不延长 24h 签名寿命。** 冷却结束后执行前还要取得当前同一命令的有效双签，过期签名不能因等待而变有效。刷新同一命令的签名不重置已公开的冷却；换根、policy 或 release 不能继承旧冷却。无公开写入/回读适配器即不能激活。

## 阶梯：10% → 25% → 50% → 100%

初次只能进入第0级的 10%。每个级别把上述三个维度的基础额度分别乘本级百分比并向下取整；单笔/滚动 <20 的硬边界继续独立生效。

每升一级要在**当前激活周期**完成至少连续 10 笔真实结算、按时留回执、按时经独立审计 approve 的付款，且没有任何未对账或未审付款。预留、模型草稿、未知、重复交易、逾期审核、曾经出现 anomaly 的付款都不能凑数。达到10笔不自动升级：新命令绑定完整资格快照和前次 activation，重新双签、公开、再冷却；不得跳级，前一级的10笔不能重复计入后一级。小数额度取整后为零就没有可用预算。

## 异常即冻结；解冻需双签和新 release

任何已登记**模型审计执行器**（不包括 GitHub 基础设施身份）可用 `payment_anomaly` 角色提交原生 `anomaly` 响应签名。绑定当前 activation 摘要、policy、release、authority、freeze_sequence；验签成功后立即事务持久冻结，保留原报告和证据摘要。单方能报告已证明的异常，不能单方解除；无效、过期、错范围或重放的报告不能制造新冻结/重复事件。

原有回执/审计逾期检查同时在 alarm、每次预留、派发前与激活事务执行，调度器漏跑也会冻结。解冻要求所有已执行/预留款项先完成独立对账和审核，千问＋豆包重新对**当前冻结轮次、从未用过的新 release、资格快照**双签，重新公开并冷却，从 10% 开始。旧签名、旧 release 回滚、单个模型、个人身份、配置布尔值或晚到的正常审计均不能解冻。解冻发布期间再有异常会改变冻结轮次，正在等待的解冻自动失效。已广播的交易不能被事后冻结撤回。
