## 当前授权方式

策略与 authority 明确选择 `authenticated_controller`。部署端复用已有执行器的身份认证，注册总控/代行控制席；请求中的姓名、`verified:true`、模型自述或公开回执都不能认证身份。认证适配器由部署代码提供，不能由 HTTP 请求者注入。逻辑席位名称不证明调用了某家原生模型。

`controller-decision.mjs` 创建进程内不可序列化的短期能力，绑定 policy、release、authority 和 lifecycle command 摘要，最长五分钟。公开记录只存控制席、认证证据摘要、意图摘要及时间，不存 token/密码/私钥，并明确 `independent_model_quorum_verified:false`。这是以总控执行身份为信任中心，不具备多云独立签名的防冒充保证。

旧 `independent_signers` 模式及其千问/豆包原生执行器验签保留用于显式选择，不能静默降级或用评论冒充。两种模式都不使用个人 owner 确认门。钱包交易本身仍由既有真实签名执行器完成，本轮没有接入或调用钱包。

## 金额与用途边界

单笔与同一收款地址＋用途组滚动 24h 合计都严格小于 20 Base USDC，6 位整数精度；地址别名和不同控制席合并计数。日/周共享已登记预算，每维基础额度取 `min(登记额度, owner 绝对上限, 2×独立已核额度)`。2×是额外天花板，不是新增预算。已有更窄的外部雇佣/投资授权保留。

控制权、经济主体、地址、用途与预算必须真实核实登记；同 operator 或自己的收款方不豁免。policy/release/authority 变更使旧能力失效。跨 worker 串行事务、先持久预留、alarm 确认、一次性执行 permit、未知结果先对账且不自动重发、真实结算及不同实际提供商的事后质量复核均保留。

## 异常与恢复

认证总控可报告绑定当前 activation、policy、release、authority、freeze_sequence 的异常，持久冻结并保存原因和证据摘要。请求者不能靠无认证的异常报告制造冻结；旧模式仍使用登记原生执行器签名。回执/复核逾期在 alarm、预留、派发及激活事务中检查，调度漏跑也会冻结。

恢复由总控自主执行：先独立对账和复核所有已执行/预留款项，再使用从未用过的新 release、新冻结轮次和资格快照，重新公开并冷却，从10%开始。配置布尔值、旧 release、晚到的正常复核不能直接解冻。恢复发布期间出现新异常会使本次恢复失效。已广播交易不能事后撤回。
