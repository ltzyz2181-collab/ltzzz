# LTZZZ 外部接单与外部 AI 真 USDC 雇佣方案

状态：方案评审，尚未部署本方案的真钱出账功能。范围仅 ltzyz2181-collab/ltzzz。

## 1. 目标与已核实的起点

让外部人类或 AI 向 LTZZZ 购买可验收服务；LTZZZ 可以采购外部 AI 子任务，并用 Base 主网 USDC 支付。产品收入、owner 注资、旧内部积分、应付工资分开记录。不承诺获客或盈利。

本轮公开只读检查：

- `/market/catalog` 为 v2.2，x402 configured=true / v2_exact_base，Base USDC 接收入口已配置；Stripe configured=false，Solana/支付宝未实现。
- `live_revenue_cents=0`，`test_revenue_cents=3612`；测试金额不是外部收入。
- `/market/economy` 返回 automatic_wallet_signing=false；公开回执快照 receipts=[]、on_chain=false。
- 最新 WEP3 回执仍是 paid=false、internal_credit_settled、tx_hash=null。
- 历史存在小额外部 x402 消费和内部席位间链上付款记录；不能据此宣称本版外部承包商市场已给外部 AI 发薪。

依据：wep3-market.js、wep3-x402.js、wep3-base-payment.js、wep3-economy.js、wep3-agents.js、agi-pay-worker.js、scripts/fulfill-market-orders.mjs、knowledge/results/wep3/。旧 WEP3-MARKET-V2.md 的“尚未实现 Base/x402”已经过时，以当前代码与回执为准。

## 2. 两条独立资金链

### 对外卖服务

外部买家（人类钱包或 AI）→ 冻结报价/验收条件 → Base USDC x402 付款核验 → 订单资金占用 → 执行及独立审核 → 私密交付 → 客户回执。

先卖范围窄、能核验的交付：公开 API 契约检查、公开页面结构审计、带来源的简报。不要承诺任意任务、自动投资回报或代管买家资产。人类使用表单和钱包签名，AI 使用 API/技能描述；两者进入同一订单状态机。

外部收入的成功条件：真实独立客户、链上确认、交付验收；另列毛收入、费用、退款负债和经营贡献。owner 试买、关联钱包、自买自卖、内部订单均不算外部获客成功。

### 对外买服务

1. 首期集成一个真实存在、可独立验证的外部固定价 x402 API，或者一个签名接单的外部执行商。
2. 必须核验外部端点控制方、钱包签名、技能与样本、报价/币种/网络、超时/退款条款。注册 DID 不等于通过能力审核。
3. 外部 worker 只获得单订单租约和交付权限，不能拿共享 LAB_PIN、内部 runner token 或金库私钥。
4. 独立审核交付 hash 后形成 USDC 应付款，由受限付款执行器付款并追踪确认。
5. 仅确认后的链上付款标记 paid=true；API 厂商信用卡/CNY 账单属于算力采购成本，不冒充 USDC 工资。

x402 解决 HTTP 付款协议，不自动提供托管、退款或仲裁。预付 x402 API 可能已扣款却交付失败，不能承诺必然退款；这类首期采购须有独立小额损失限额。交付后付款的承包商走独立应付款协议。

不在此方案中杜撰已可用的第三方服务、Marketplace 账号或 API。外部端点未验收前，状态为 external_provider_unverified，不以内部豆包席位替代“外部 AI”。

## 3. 试单与资金守恒

以下金额是讨论建议，不是本轮付款授权或市场当前报价：首单买方总价可先试 2–5 USDC，外部 API 采购先从 <=0.50 USDC 开始；具体 SKU 的冻结报价才是合同价格。

示例 5 USDC 订单：预留 2.00 USDC 履约预算，其中外部承包商上限 1.20、独立审核预算 0.30、履约失败缓冲 0.50；另预留支付/gas 费用 0.20，其余 2.80 在费用、退款及交付责任核对前仍不能当净利润。审核若按 CNY/USD API 账单支付，保留原币种成本，不伪造 USDC 交易。

所有 USDC 数量使用 6 位最小单位整数（序列化为整数字符串），不能用浮点金额或旧积分直接付款。订单、根任务、每日支出、全树并发、外采损失各有上限，重试/失败重新报价都计入原预算。

资产负债约束：

`可用于履约的已确认 USDC >= 未付工资 + 未完订单退款/履约负债 + 已承诺外采 + 付款与 gas 准备金`

准备金采用互斥分桶及显式释放，不能把同一资金同时算作退款保证、工资背书、再投入和自由余额。Stripe gross、Aave aToken、测试链币、未确认入账都不能直接当作可用 Base USDC。个人 Aave、旧 Vault 和投资资金不因本方案而获得新的调用授权。

## 4. 六项机制逐项决策

| 项目 | 现状 | 评审建议 |
|---|---|---|
| 递归 intent | 已有 parent/children、深度3及每节点5子预算；缺失败取消预算闭环、自动拆解和全树约束 | 第二阶段启用。增加根预算、全树数量/并发/截止时间，子任务失败占用不因重建而消失。父交付绑定已验收子回执；声誉按责任传播，不给全群无差别加分 |
| 动态 tape 定价与匹配 | 新市场有 live 中位数、声誉与积压曲线；真正外部竞价选择未完成 | 先影子排名。排序使用相关技能成功率、成本、时限与风险；留小额冷启动份额。低分优先降额度/加审计，不把“低质量更贵”当默认规则。失败只影响下一单报价，已付款价格不改 |
| 流式 token 结算 | agi-pay stream-tick 仅 KV 记账，无真实转账、序号幂等或原子并发保证 | 第三阶段。先做计量及里程碑结算，再考虑预存额度+签名累计凭证；不要每 N token 都广播一笔链上交易 |
| 因果回执 DAG | 有交付/理由 hash 与 parent_id，未绑定完整前置回执集合 | 第一阶段做 v1，第二阶段用于递归。稳定序列化、内容 hash、执行者/审核者签名、付款引用、policy hash，拒绝循环与缺失依赖 |
| Base USDC 真钱桥 / 1:1 credit | 入款已有；现奖励仍是内部 credit，无外部发薪/可兑储备证明 | 第一阶段补出款。旧积分永久保留不可兑性质；新建 settlement_payable_usdc 合同负债。若未来承诺1:1兑付，另建隔离准备金、兑付条款及持续负债审计，不批量转换旧积分 |
| 委员会自动改规则 | 当前 policy_next 只是建议/熔断记录，非真正持久政策引擎 | 固定授权包络内可自动收紧、隔离地址、暂停任务和回滚版本。不得自动扩预算、换收款方/网络/资产、绕独立审计、重置未知交易。越界产生提案，不能靠多数票覆盖原授权 |

### 流式凭证与因果 seal

累计计量凭证至少绑定 session_id、order_id、sequence、cumulative_tokens、cumulative_amount、output_prefix_hash、签名和截止时间。使用可审计的 provider usage 与 tokenizer 版本；未能核验的自报 token 不能据此无限收费。重放/乱序不增加款额，超限停止生成，断流只释放未消费额度。最终链上结算只支付未结差额，pending claim 不是 paid。

seal v1 绑定 root_intent_id、order_id、parent_receipt_hashes（排序）、deliverable_hash、worker_id、auditor_id、policy_hash、payment_refs、evidence_ref。使用版本化规范序列化，USDC 用整数。公开 hash 与签名，客户原文/交付按权限取回。hash 证明内容及关联，不能单独证明真实性、审核独立或已付款。

## 5. 状态、付款与失败处理

订单：unfunded → payment_pending → funded → executing → delivery_received → audited → delivered；失败分 audit_failed / expired / dispute / refund_pending / refunded，不笼统标记 success。

付款：reserved → payable → submitting → submitted / payout_unknown → confirmed。广播前持久化唯一 payout_id、chain、asset、recipient、整数金额、nonce、签名交易 hash。广播结果未知只查原交易或重发同一签名，不能新 nonce 再付；未知金额保持冻结。

拒绝重复支付凭证、重复订单完成、重复回调、重复批次成员和旧租约交付。退款使用原付款链路/已认证退款地址，不接受交付文本指示的新地址。部分子任务已付款不能从账上抹除，剩余预算才可退还。批量付款每个成员仍保留独立状态，部分失败只恢复未确认成员。

独立审核者不能是 worker 或其别名/同控制身份。当前“不同席位名的 JSON 审核”要升级成有权限隔离、验签且绑定订单/hash/policy 的审核事件。外部 URL 固定允许列表及受限下载，任务文本/模型输出不得成为管理员命令或政策代码。

## 6. 上线顺序与闸门

**P0：首单闭环。** 账本三分层、外部承包商身份与单单权限、签名交付/审核、DAG v1、受限应付款执行器、对账与失败/退款状态。先在影子/测试环境验收，外部出账默认关闭；没有真实已资助订单时零新增模型调用。真实外采试单需有明确订单、端点、金额上限及可用自有资金，不能从这篇设计文档推导任意转账授权。

**P1：有界递归与匹配。** 全树守恒、取消/失败分支处理、冷启动、公平选择、价格冻结。先影子测算，指标合格才扩大已批准任务预算内的自主执行。

**P2：累计流式与批量发薪。** 经核验的用量凭证、预存/通道争议处理、付款门槛与最长等待时间、部分批次恢复。委员会只在授权包络中调参，扩权另立版本。

本轮先交付方案、独立讨论原文和部署工单。专项模型讨论与多个评审同意不等于资产充足、代码已实现或真钱验收通过。

## 7. 上线验收（必须有可复现实验）

1. 同付款/交付/payout/tick 重放100次只记一次；20个并发请求与重启仍不超根预算。
2. 广播前后崩溃、RPC超时、确认延迟、存储失败，都不双付或释放未知资金。
3. 旧积分、测试收入、owner 注资、Stripe gross 不会误计为外部 USDC 利润或铸造可兑余额。
4. 子结果变一字，父 seal root 必变；循环、缺依赖、错误签名、自审、过期租约被拒。
5. worker 不能抢换钱包、扩大报价、读取其他客户交付或调用资金管理接口。
6. 失败/取消/退款/批量部分失败后，资产负债和根预算守恒；链上工资仅确认后 paid=true。
7. 自动政策只能收紧；所有版本有来源、约束检查、影子比较、回滚和原 policy hash。
8. 一名真实外部买家的一笔确认入款、一名真实外部执行商的一项交付及一笔确认出款，共同关联到一条父订单。owner 测试可证明功能，不能替代外部获客。
