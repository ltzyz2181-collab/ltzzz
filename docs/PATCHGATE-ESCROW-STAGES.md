## PR #223 修订：分类、证据与签名分工

H1：取消 `scripts/` 整体 L1。运行脚本默认 L3，资金、钱包、签名、国库、鉴权脚本改名也不能落入普通脚本白名单；目前只有测试目录保留通用 L1。未来若开放普通脚本，须单独审核并明确列出路径，不能重新放开整个前缀。

H2：L0 只涵盖普通 `docs/**/*.md` 与 README。回执目录、结果、台账、Memory 及六份原文均 L3。回执额外要求由 base 的 `receipt_writer_rules` 最长匹配前缀授权 executor，并持有 base 公钥的 `receipt_write` 角色，签名绑定完整 subject 与实际写入路径。手写 accepted/paid、双模型口头同意不能代替认证。当前已登记实际传输者，签名 keys 仍为空，未开启签名准入；不能把登记名字说成签名已配置。

H3/H4：整个 base 信任根中，一个 executor 只能映射到一个 provider，含已停用历史密钥；允许同 executor/provider 下轮换不同密钥，不允许一个公钥挂在不同 executor 身份上。checks 与 deployment 的签名 executor 必须不同于作者，且有明确登记角色；review 同时要求 executor 与 provider 均不同于作者。登记身份须核对真实执行入口，不能由模型自选两个名称证明独立。

M1：特权审计不再由候选分支 push 或 PR 触发，只接受 main 上显式 workflow_dispatch，并把 runner 固定为该 main 事件的完整 SHA。候选只用 Git ls-tree/cat-file 读取固定清单中的普通 blob；不 checkout/import/运行候选模块，不跟随候选 symlink，不将候选代码路径用作审计器路径。提供商适配器与 Skill 取 main 的可信检出。main 无此审计器时如实阻塞，不能给候选脚本注入 Key。本轮按 owner 指示，千问工程复核通过已有 main 队列消费者执行，输入为绑定新 head 的源码摘录，范围如实记录。

此修正约束本审计工作流，不宣称改变了 GitHub 全仓 Secret 的分发策略或管理员权限；平台级环境隔离须另有实际配置回读。

## PR #224 条件收尾

N1：通知必须由不同于作者的 base 登记执行器签名，reference 只接受本仓确切 `#issuecomment-ID`。签名绑定评论原字节 SHA256、评论 actor 和 subject 哈希；可信采集器从固定 GitHub REST 评论端点独立回读，拒绝重定向/404/引用不符，正文必须唯一包含原 Task ID、完整 head、subject 哈希及 owner mention。评论编辑、head 改动、actor 改动、超过 freshness 的读回会作废。回读事实由受信采集器单独传入，不从 PR 的“已通知”字段或签名者自报的布尔值获得。通知是投递证据，不代表 owner 阅读或批准。

N2：`ops/dispatch/inbox/` 与 `ops/dispatch/queue/` 下普通 `.md/.json` 派单卡降为 L1；`.mjs`、AGENTS、密钥样式路径、台账、授权文件、`ops/dispatch/receipts/` 仍为 L3。登记现有 GPT GitHub 中转、主线千问 consumer、主线派单哨兵，附账号或实际 workflow/run/head 证据；回执路径使用最具体的 writer 规则，千问 writer 不因此获得其他资金回执目录权限。A1 可以只读观察这些通道；A2 签名准入不得在 keys 为空时开启。

千问配置证据保留真实文件内容、原字节哈希和旧 revise 原文。真实现状是 `trust.enabled=false / keys=[]`，并非“已经有生产签名人”；测试中的短期密钥和签名载荷明确是夹具。提供这些证据用于关闭 A0 材料缺口，不把未部署的生产签名能力写为通过。

N3 扫描噪音作为低项保留；A1 只观察、提示，不因启发式误报撤销席位或阻塞现有主线流程。A2 自动放行前另审扫描分级，当前不称“扫描无发现=安全”。

## 可信执行与身份

生产观察器必须把策略、公钥、检查器及其导入依赖固定到受保护的 base SHA；PR 只作为 Git blob/diff 数据读取。不使用 `pull_request_target` 检出 PR head 执行代码，不将 PR 正文拼进 shell，不向候选测试注入平台凭证。完整文件列表、模式和 diff 由 Git 生成，不能由 PR 自报 touched_paths 决定等级。

`scripts/patchgate.mjs inspect <base40> <head40> <原TaskID> <输出.json>` 从 Git 的 base 对象读取配置，只产检查回执。初次引入时 main 没有基线配置，命令会报缺配置；bootstrap 必须经过外部双审，不能拿新检查器自证上线。

审计/作者/检查/部署证明使用独立执行器 Ed25519 公钥登记，签名绑定仓库、原 Task ID、base/head SHA、策略/公钥配置哈希、全体差异哈希、角色和 UTC 时间。提供商取已登记执行器身份，上游模型取提供商响应；模型文本和共享 GitHub 用户名不能证明来源。签名证明的是受信执行器作出的声明，**不是原厂模型提供商对模型输出的密码学证明**；A1 必须审计签名执行器确实调用对应上游，并隔离各签名密钥。同一公钥不能伪装两个提供商。此处的证明密钥不授予钱包控制权。

检查证明另绑定 `checker_base_sha`，且签名 executor 与作者不同；候选修改过的测试不能替代基线约束，候选新增测试也要跑。A0 只验证证明格式、签名和绑定，尚未接 CI 证明签发器。所有 workflow 在本期保守升为 L3，待权限语义解析器和可信 workflow 适配器单独过审后才区分普通 L1 workflow。Memory 及回执等可执行控制输入不按普通文档合并。

L3 需要两位不同于作者且相互不同的真实提供商；24h 三次**已签名、去重**失败增加一份复核，不停用席位。拒收记录保留并处理，不改写成通过。A0 无处配置、生成或读取私钥。

敏感名称（如 `docs/credentials.md`）刻意升 L3，文档后缀不能豁免；`memory/promote/` 的 L3 优先级高于普通 Memory 文本规则。当前扫描器保守拦下新动态执行和未登记域名，不凭模型一句“安全”自动放行；修改提案或单独审计可信规则变更后再检查。

## 复验与幂等的实际边界

五项确定性复验为：目标/提交绑定、可信白名单内的 HTTPS 无跳转和原字节哈希、专用元数据正文及响应头提交一致、Date 落在观测窗口且 HTTP Date/平台观测/观测结束都在本次验证 freshness 内、Cloudflare 当前活跃版本与预期及响应头版本一致且流量 100%。时钟偏差最多单独容忍5秒，不能把数个 freshness 窗口相加。A3 的专用元数据目标须返回仅含 `schema="ltzzz.patchgate.canary.v1"` 与 `source_commit` 两项的 JSON；页面/注释里碰巧包含哈希不算通过。白名单在评估器与独立复验函数两层检查。日志打印版本不代替平台 API；模型误读不能把确定性复验降回拒收，但模型提出的其他真实缺陷仍须处理。观测文件哈希存外置回执，不要求文件包含自己的哈希。

专用正文固定为两字段按键名排序的紧凑 JSON 加一个 LF，避免重复键、正文中埋入哈希或解析器差异；A3 采集器和测试目标均须遵守这份格式契约。

含 Worker 的混合 L2/L3 补丁在提高复核级别后，仍保留隔离复验前置条件，不能加一个高风险配置文件反而免去 Worker 复验。diff 扫描区分文件头与 hunk，新代码以 `++` 起行也完整扫描。扫描是保守启发式检查，不承诺覆盖所有密钥格式或动态外联方式；**无发现不得称为安全结论**，回执固定 `scan_safety_conclusion=false`。本轮补 Function/spawn/WebSocket/协议相对 URL 与 sk- 误报回归；字符串拼接/编码等仍可能不被发现。GitHub URL 收窄为本仓路径，不能把整个 github.com 当可信出口。

函数处理的是签名执行器提交的观测数据；本期没有实际 HTTP/Cloudflare 采集器，不把构造测试数据称为生产复验。A3 才接经过审计的采集器。回滚权限和上一成功版本没有实测，所以自动回滚保持 false。

预留键为 `task_id:head_sha`，动作分别去重。`reserveAction` 只提供同一持久文件系统上的原子创建；不是多台 Actions runner 的分布式锁。预留后状态未知必须对账，不能删预留重跑。A1 接共享存储 CAS 后，A2/A3 才能启用有副作用的操作。

预留不自动过期解锁：A1 必须提供对账入口，读取原 run/合并 SHA/部署 ID/原交易，以可回读结果关闭原动作；证明未发生副作用才可在新授权的执行尝试中继续，不能按超时直接重复。A2 合并前还须确认 base SHA 仍等于目标分支 tip，base 前移后旧检查与签名失效；当前没有合并适配器，未声称这两项已在线上跑通。

## Escrow 必须修正的边界

合约只接受部署时配置的测试币，使用 SafeERC20、检查实际到账、不支持扣税/重基准币；CEI 与重入锁覆盖创建、放款、退款。EIP-712 域绑定 chainId 和合约地址；签名结构绑定 escrowId、出资人、固定收款人、token、整数金额、taskHash、deliveryHash、验证器集合版本及 deadline。拒绝重复地址/提供商组、低质量签名、跨订单/链/合约重放，必须是三个登记提供商中的两个。模型本身不保管私钥，执行器签署哈希绑定的原生复核结果；合约只能验证登记的签名者/组，不能自行证明模型调用来源。

固定三个验证者及各自提供商组，不留上线后任意替换为同一控制人的管理入口；需要轮换就按单独审计的新合约迁移，已创建订单的验证集合不变。放款只能在 deadline 之前且未暂停时一次成功；deadline 到达后只允许退款给原出资人。退款不受暂停影响，任何人可触发，不能退给 relayer；暂停不能永久锁住出资款。日常 relayer 被盗不能改受益人、金额或绕过签名。

每笔、累计未结敞口使用显式整数基础单位上限；部署后只能调低。不得从“历史已验证额度×2”猜出本次真钱预算。初始受益人白名单只含 owner 已核验控制的测试地址，未验证不能填旧 Agent 地址代替。

“超时退款”是合约允许任何人到期触发；区块链不会自己发交易。B1 必须验证无资金权限的 keeper/relayer 定时触发退款、未知交易按 escrowId 对账，以及无 keeper 时出资人仍能手动退款。尚未证明这些时不得声称全自动。
