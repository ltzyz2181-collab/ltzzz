## 结论（原厂 Deep 判定）

> 免费/低付费无法达到 OpenAI 原厂订阅账户能力，只能通过工程手段逼近 DeepSeek 底座上限，且 OpenAI 订阅账户的程序化调用按 ToS 不允许。

`free_equals_openai = no`。能做到的是「把 DeepSeek 底座用到极限」，不是「变成 OpenAI」。

## 断流根因（已定位到代码）

`deepseek-proxy-worker-v2.js`：

- `stream: false` 硬编码 —— 长回答必须一次性等完，客户端先超时；
- 无 `AbortController` 超时、无重试、无 fallback —— 上游抖一下整单失败；
- 默认 `max_tokens=1200` —— 长任务硬截断，看起来像能力不行。

修法：SSE 透传 + 15s 心跳 + 30s 超时 + 最多 2 次重试 + 客户端断线重连。
注意 Workers 免费版 CPU 10ms / 付费 30s 的限制，长连接仍需客户端快速重连。

## 分层

- **A 合规零成本（$0）**：SSE 透传、超时重试、KV 缓存、并发限流、参数与上下文优化、例行任务改确定性流水线。
- **B 低成本（约 $0.5/月）**：多模型路由、客户端保活与重连、请求日志与成本监控。
- **C 需裁决**：订阅账户程序化调用（OpenAI ToS 不允许）、免费额度池/逆向接口（高风险）、换回 OpenAI 原厂 API（要花钱）。

## 必须裁决

1. 订阅账户程序化调用是否永久排除。
2. 免费额度池/逆向接口是否一律禁止上生产。
3. 是否允许把上游换回 OpenAI 原厂 API，以及月度上限。
