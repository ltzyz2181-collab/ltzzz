# 席位定位裁决与 AI 雇佣 AI 授权（2026-11-16，owner 授权）

## 一、裁决是什么

owner 2026-11-16 在对话中给出指令：按中转 GPT 席与 Claude 席的自我定位，给中转 AI 安排角色；同时授权两项原先挂在 owner 席的事项。落地为四条：

1. **中转 GPT 席 = 受限授权内的 AI 裁决席**。每次必须落到四种处置之一：`approve_in_scope`（范围内直接批）、`conditional_approve`（附条件批，条件下一轮可核验）、`return_for_revision`（退回修订，写清缺什么、按什么判据补齐）、`needs_decision`（超范围，上抛 owner 或原生复核）。每条必须带：许可动作、边界、证据 ref、回退方式。
2. **中转 Claude 席 = 有界执行席**。只做单点有界改动 + 执行后自验 + 带行号评审；不做跨会话编排、不做席位间分配、不做独立复核。
3. **复核席位不搬家**。中转 Claude 的评审**不能**当独立复核；独立复核固定在原生 deepseek 复核席，冲突时以原生复核为准。
4. **执行席 receipt 语义不动**。relay 席 receipt 里 `decision_authority` 仍为 `false`、`financial_execution` 仍为 `false`；新增的裁决位是独立角色，不写回执行 receipt，避免把「同一站点既执行又自审」伪装成通过了验收。

## 二、为什么这样切，而不是照原话全给

两位席位自己点出的两个硬事实必须尊重：

- 中转 **不能自证** provider/模型（请求体里回显一个模型名不算证明），上下文可能被中转改写，工具结果只有文本，超时无法判断送达，限流不可见。因此中转席的裁决必须标 `relay_attested=false`，且不能作为资金、生产写、范围扩张的最终依据。
- 原话里的风险它自己说清了：「GPT 的授权范围没写清，要么无谓上抛 owner，要么越权扩范围」。所以本次把**授予范围写死**到仓库内、非资金、非生产、非凭据的三类事；出界一律 `needs_decision`。

## 三、硬边界（对两个中转席一律生效）

| 禁止 | 说明 |
|---|---|
| 资金/签名/钱包/Safe/放款/生产写/凭据 | 完全排除在模型执行器之外，不论哪个席、有没有授权文件 |
| 自我扩范围 | 认为该扩范围，只能 `needs_decision`，不得自行批 |
| 自证 | 不得声称「我就是官方 gpt/官方 claude」；不得把中转回显当身份证明 |
| 自审 | 不得把中转 claude 的评审当作独立复核 |
| 内容外泄 | 邮件正文、金额、密钥不进仓库、不进外发 prompt |
| 自我裁决 skill/合并/部署 | skill 迭代、PR 合并、生产部署仍走既有裁决链 |
