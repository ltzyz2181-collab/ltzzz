# 立项连续性：为什么任务会干一半停住，怎么让它持续下去

日期：2026-11-17 ｜ 触发：Owner 提出「每个任务干一半都停住」

## 一、先说结论

任务停在半路，不是因为席位不干活，而是因为系统里**没有"下一步"这个字段**。

仓库里每个流水线都只负责自己那一段：派单卡 → 一次模型调用 → 写回执 → 结束。回执写完之后，没有任何东西会再读它、判断"下一步该谁做什么"。于是：

- 需要裁决的，停在"等 GPT"；
- 需要外部证据的，停在"等平台"；
- 需要 Owner 给值的，停在"等 openid"；
- 本来就没人阻塞的，也停在原地——因为没有排队机制把它捡起来。

## 二、仓库里的实测证据

| 现象 | 证据 |
| --- | --- |
| 钱包 P0 已合并，但没进 CI | `small-payment-policy.yml` 只跑 `scripts/tests`，`scripts/wallet/__tests__`（21 项）从未在 CI 执行过；只有本机能跑 |
| 定时任务永远绿 | `ltzzz-wallet-ops.yml` 每一步都是 `... || true`，失败也被吞掉，6 小时一次照常"成功" |
| 队列一次只消费一张 | `run-qwen-dispatch.mjs` / `run-doubao-dispatch.mjs` 每次 run 只取第一张无回执卡；推一张就跑一张，推三张只跑一张，剩下的要再有人推 |
| 决策点没有默认动作 | `PR #408`、Wallet P1、退款 F1–F7 都停在"待裁决"，卡里没有 deadline，也没有"到期未裁决则如何" |
| 交接靠文档 | 派单卡写的是 instruction，不写"谁在什么时候接手下一步" |

## 三、机制：一张看板 + 一条硬规则 + 一个看门狗

### 1. 一张看板（`ops/task-continuity/board.json`）

每个立项任务一条，结构固定：

```json
{
  "id": "WALLET-P1-INCREMENTAL-VERIFY",
  "title": "…",
  "state": "ready | in_progress | in_review | blocked_decision | waiting_external | waiting_owner | done",
  "next_owner": "claude | doubao | qianwen | deepseek | gpt | owner | deploy_seat",
  "next_action": "现在就该做的那一件事",
  "unblock_condition": "blocked/waiting 时必填：什么条件一到就解除",
  "updated_at": "2026-11-17T11:00:00Z",
  "evidence": ["…"]
}
```

规则由代码强制（`scripts/task-continuity.mjs`）：

- 非 `done` 必须有 `next_action` 和 `next_owner`；
- `blocked_decision` / `waiting_external` / `waiting_owner` 必须有 `unblock_condition`；
- `done` 必须有 `evidence`；
- 状态与责任人只能取固定枚举，写错直接失败。

### 2. 一条硬规则：席位结束前必须写下一步

任何席位（Claude / 豆包 / 千问 / Deep / 部署席）交付后，必须做两件事之一：

- 把任务的 `state` 推到下一个状态，并写清新的 `next_action` + `next_owner`；
- 或者把它改成 `blocked_*` / `waiting_*`，并写清 `unblock_condition`。

不允许"回执写完就消失"。回执只证明这一段做完了，不证明任务在走。

### 3. 一个看门狗（每 6 小时）

`task-continuity.yml` 定时跑看板，输出：

- 现在就能做的任务（按滞留时长降序）；
- 等条件/等裁决的任务及其解除条件；
- `ready` 超过 24 小时未动 → 告警；超过 72 小时未动 → `--strict` 下判红。

它不调用任何模型、不写仓库、不动钱。

## 四、为什么这能解决"Deep 团队协调不好"

协调不好通常不是沟通问题，是**状态不同步**：Deep 看到的、Claude 看到的、豆包看到的各是一份文档。看板把三件事变成唯一事实：

1. 现在有哪些任务没做完（而不是"我记得还有几件"）；
2. 每一件下一步归谁（而不是"等有人处理"）；
3. 卡在什么条件上（而不是"好像缺个东西"）。

## 五、使用

```bash
node scripts/task-continuity.mjs           # 人读
node scripts/task-continuity.mjs --json    # 机器读
node scripts/task-continuity.mjs --strict  # 有超期 ready 任务时退出码 2
```

改看板就是改 `ops/task-continuity/board.json`，PR 会跑结构校验；格式错直接红。

## 六、边界

- 看板只是状态机，不是授权：它不能让任何任务越过 GPT 裁决或 Owner 授权。
- 不改资金策略、不自动派单、不替代 review。
- `state=done` 需要证据路径；没有证据的"完成"写不进去。
