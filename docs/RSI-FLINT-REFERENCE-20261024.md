开发方称 Eureka Machine 参与架构、训练、量化和推理优化；它自动提出想法、实现、实验、验证、选择下一步，能保留与组合有效分支。研究文章公开部分实验工件，并明确提及反复种子验证、检测缓存答案/利用评测漏洞等reward hacking以及人工/AI检查。本文未独立复现其benchmark或训练；厂商速度/榜单不是LTZZZ实测。模型权重和研究系统是两层，下载Flint不能自动获得完整的Eureka研究平台；当前读取材料没有证明无限递归自我提升已实现。

## 最小实验建议（未执行、未新增调用/定时）

1. 从真实失败记录选一个固定Task ID，保存来源提交、原始症状和基线。先查旧回执，不重复派单。
2. 从可信main固定评测版本；候选不能修改约束自己的检查。补可回放反例，并留未给作者答案的独立保留样例，避免只通过公开样例。
3. 用现有已授权渠道产生有限候选，每个候选独立分支/版本；不因提出RSI概念新添付费cron、GPU租赁或模型Key。
4. 确定性测试与实际运行证据决定是否达到指标，模型意见另外保留。复核者与作者为不同实际提供商，未知身份不猜。
5. 按当前分期授权处理候选；A1阶段只交PR及测量，不能越级自行合并/部署。拒收/失败原文保留。
6. 将获审的有效改进、失败原因和下一轮选择依据记入可回读工件；Memory仅形成有来源的待审候选，不直接覆盖记忆原文。

测量至少包括：真实问题修复率、保留样例通过率、已有行为回归数、单次模型成本/调用数、从发现到验收的耗时、同类缺陷下一轮是否复发。派单数量、模型自称进步、一次自审approve不算提升。

## 何时考虑本地 Flint

先核硬件与runtime，再拿相同真实任务对比当前国内模型的通过率、总时延、内存与总成本。官方提供rec、Ollama、llama.cpp、Cline等接线资料；本机是否支持、权重变体和工具调用均须实测。本轮没有安装、购买硬件、注册新账号或触发模型训练。优先借鉴研究/评测闭环，是否引入Flint由实际对照结果决定。
