# 客服通道实测与首条消息回复（2026-11-13）

## 一、结论先行

1. 微信客服这条人工通道的堵塞点已定位为**平台侧结构缺失**，不是操作失误：
   「客服小助手」账号 印章擎天柱（客服管理员）在「切换账号 → 选择当前服务的小程序」里**只有「卓省丨北京店」，没有「世章 AI 助手」**，即该微信号从未被绑定为世章小程序的客服人员。
2. 世章小程序后台（新版）**不存在「客服 / 客服人员」入口**：左侧菜单无该项，成员管理无客服区，开发管理-接口设置无客服消息权限项，设置-基本设置页底亦无相关配置。官方文档描述的「功能 → 客服 → 客服人员 → 添加」路径在本账号后台不可达。
3. 因此改用官方允许的第三条下发方式：**调用发送客服消息接口**。已完成 AppSecret 重置 → 换取 access_token → 向订单买家推送首条答复，接口返回 `errcode: 0, errmsg: ok`。

## 四、边界与风险（必须如实记录）

- **额度窗口已重置**：客户在 15:21 回消息后，按官方规则重新获得 5 条 / 48 小时的主动下发额度（从客户最新一条消息起算）。
- **仍读不到客户消息**：本账号没有配置消息推送（云函数未接 `message/custom` 回调），因此客户后续发来的文字和图片（含会话里已有的台账照片）我们**无法通过接口取回**，只能靠人工在手机端「客服小助手」或绑定的客服人员看。这是当前最大的缺口，比"能不能回"更关键——"能不能看见客户发了什么"。
- **AppSecret 已轮换**：旧密钥立即失效。已核查线上 5 个云函数（order-list / order-query / pay-create / vpay-order / vpay-notify）环境变量中均无 AppSecret，微信支付使用 V3 商户私钥（`WXPAY_SERIAL_NO` / `WXPAY_PRIVATE_KEY`），故本次轮换不影响支付链路与订单查询；后台提示「可能导致小程序无法正常运行」的风险点应为其他依赖 access_token 的能力。
- **新密钥只显示一次**：未写入仓库、未写入本文件；已按上文第 6 条方式加密保存。要让这条通道长期化（自动回复、按订单号应答），必须把新密钥注入云函数环境变量，并新增客服消息回调函数——这属于改线上配置，需 Owner 明确指令后再做。
- **无法直接观测客户侧**：本次以接口返回码为成功依据，未看到客户手机端的实际展示；客户若继续在会话内发消息，目前仍无自动回复（线上无客服消息回调/自动回复云函数）。
- **客服人员绑定入口缺失**属平台侧问题，需向微信侧确认是后台改版位置变动、账号权限不足，还是该模块未开通；在解决前，「客服小助手」人工工作台路线对世章不可用。
