# LTZZZ Web3 长期项目规划 v0.1

## 目标
建立与 LTZZZ AGI 实验室配套的开放、可审计、可逐步治理的 Web3 基础设施。Web3 不是独立的投机项目，而是服务于身份、公共资金、AI 支付与可验证协作。

## 四层结构
1. **身份层**：LTZZZ 项目身份、AI Agent 身份、任务 ID、贡献记录。
2. **资产层**：独立资金池、链上地址、捐赠记录、预算与账本。
3. **治理层**：多方签名、额度限制、提案/批准/执行/审计分离；任何单一 AI 或个人不能独立支配公共资金。
4. **应用层**：AI Agent 小额支付、AI 服务采购、实验项目资助、公开账本与贡献证明。

## 第一阶段：可验证，不自动放大风险
- 统一 PAY-ID / DONATION-ID / TASK-ID。
- 链下台账与链上交易 ID 关联。
- 小额 dry-run、余额查询、交易状态和 receipt 记录。
- Safe 多签作为公共资金治理基础；AI 只能提出/构造交易，不能持有完整私钥。
- 前端只展示公开状态，不暴露 Secret、私钥、OTP。

## 第二阶段：AI Agent Economy 原型
- GPT 总控产生支付任务。
- 其他 AI 执行研究、采购建议、代码与审计。
- LTZZZ Payment Gateway 检查预算、用途、额度和审批状态。
- 通过受控 provider 执行小额支付。
- 自动写入审计日志并通知 Telegram。

## 第三阶段：公开实验生态
- 开放任务市场/实验任务。
- 贡献者提交研究、代码、内容或基础设施贡献。
- 以可验证记录关联贡献与资金使用。
- 再考虑 token、积分或其他链上激励；在真实需求和治理规则成熟前不预设发行。

## 禁止事项
- 不因“Web3”名义扩大资金风险。
- 不让单一 AI 掌握公共钱包私钥。
- 不把个人资金与 LTZZZ 公共资金混账。
- 不把代码入库、地址创建或 dry-run 冒充真实部署/真实支付。
- 不使用浏览器自动化绕过验证码、风控或平台安全措施。

## 今日优先任务
先完成身份/任务/台账/审计闭环，再扩展支付；先小额可验证，再谈规模化。
