# 子网账本分析

## 1) 资金流向与异常

- **实际资金流出：0**  
  全部 8 条提案的 `executed` 均为 `false`，`tx_hash` 均为 `null`。因此链上/账本没有真实资金流动，只存在“记账层”的名义金额。

- **名义累计记账金额：0.1535 USDC**  
  各提案金额：  
  0.001 + 0.001 + 0.0145 + 0.0145 + 0.025 + 0.025 + 0.0355 + 0.037 = **0.1535 USDC**  
  占当前余额 `balance_usd = 0.565` 的 **27.17%**。

- **异常点**  
  1. **单一资产集中**：全部提案都是 `USDC-Aave-v3-Base`，没有分散到其他资产或策略。  
  2. **单一提案人**：全部来自 `did:ltzzz:deepseek`，缺乏多主体制衡。  
  3. **金额成对重复后递增**：前 6 条金额两两重复（0.001×2、0.0145×2、0.025×2），后 2 条为 0.0355、0.037，模式疑似脚本测试或参数扫描。  
  4. **时间频率偏高**：10-10 至 10-12 三天内产生 8 条影子提案，且最后一条时间戳被截断为 `"2"`，数据完整性存在问题。  
  5. **无执行闭环**：所有提案都是“仅记账不执行”，收益无法验证，也无法证明策略有效。

## 2) 影子提案是否合理

**在记账一致性上合理，在策略有效性上不合理。**

- **一致性合理**：  
  `status = "shadow"`、`executed = false`、`tx_hash = null` 三者相互匹配，符合“影子提案”的设定：只记录，不实际执行。

- **策略合理性不足**：  
  1. 所有提案的 `thesis` 几乎相同，只写“稳定币借贷收益，仅记账不执行”，没有给出预期收益率、持有期限、风险、gas 成本或退出条件。  
  2. `compassion_check` 全部为 `no-labor-displacement-asset`，但仅凭标签无法验证是否真的不存在劳动替代。  
  3. 金额从 0.001 逐步增大到 0.037，可能是在测试系统容差，但重复提案没有新增信息。  
  4. 如果目的是模拟配置，缺少“模拟收益回测”字段；如果目的是投资建议，则全部未执行的状态无法形成有效验证。

结论：这些影子提案更适合被视为**流程测试数据**，而不是可讨论的资本配置方案。

## 3) 3 条可测试建议

> 以下建议仅用于账本测试与流程验证，不构成任何投资执行指令。

1. **为影子提案增加收益回测字段**  
   要求每条影子提案必须附带 `expected_apy` 和 `holding_days`。72 小时后用 Aave v3 Base 的历史市场数据回测，检查实际收益率是否落在 `expected_apy ± 0.1%` 区间内。  
   - 可测试指标：收益偏差率、回测通过率。

2. **设置重复提案检测规则**  
   当同一 `did` 、同一 `asset` 在同一自然日内出现两条金额完全相同的影子提案时，自动标记为重复并告警。  
   - 可测试指标：当前数据中 CAP-00002/04、CAP-00014/19、CAP-00020/25 应触发该规则。

3. **建立影子记账占比熔断线**  
   对单一提案人累计名义记账金额设置上限，例如不超过当前余额的 20%。当前累计名义金额为 0.1535 USDC，占余额 27.17%，已经超过该阈值，应触发复审或暂停该提案人的影子记录权限。  
   - 可测试指标：累计名义金额 / `balance_usd` 是否超过 20%，超过时是否成功阻断。
