# 子网账本分析

数据范围：给定的 `balance_usd=0.2` 与 8 条影子提案；第 8 条 `CAP-00027` 的 `at` 字段被截断，完整时间无法确认。

## 1) 资金流向与异常

- 账本余额：`0.2 USD`
- 影子提案总金额：`0.001 + 0.001 + 0.0145 + 0.0145 + 0.025 + 0.025 + 0.0355 + 0.037 = 0.1535 USD`
- 影子总额占余额比例：`0.1535 / 0.2 = 76.75%`
- 若全部执行，账面剩余：`0.0465 USD`

异常点：

1. **无真实资金流出**：所有提案 `executed=false`、`tx_hash=null`，没有任何链上执行记录，无法验证资金真实可用或已被锁定。
2. **金额呈阶梯式上升**：金额序列为 `0.001, 0.001, 0.0145, 0.0145, 0.025, 0.025, 0.0355, 0.037`，存在成对重复，但账本中没有批次或意图标识。
3. **ID 不连续**：`CAP-00002, 00004, 00012, 00014, 00019, 00020, 00025, 00027`，中间跳号原因在给定数据中不可见。
4. **未记录执行费用或缓冲**：只有 `balance_usd` 一个余额字段，没有 gas、滑点、最小起投额或失败退款路径；累计影子分配后余额仅剩 `0.0465 USD`。

## 2) 影子提案是否合理

从数据自洽性看，影子提案是合理的：

- 每条的 `thesis` 都声明“仅记账不执行”，与实际字段 `executed=false`、`tx_hash=null` 一致。
- `compassion_check` 均为 `no-labor-displacement-asset`，与资产类型 `USDC-Aave-v3-Base` 不冲突。

但从资金配置角度看，合理度有限：

- 8 条提案全部为同一资产、同一 `compassion_check`，金额从 `0.001` 逐步增加到 `0.037`，但未记录收益预期、风险参数、退出条件或为何分多次记账。
- 累计影子敞口已接近余额上限，却没有预留失败空间或执行缓冲。
- 由于没有执行记录，无法验证这些影子提案是否真的可部署。

结论：作为“仅记账”的影子提案，其字段逻辑一致；但作为资金规划，仅凭现有数据不足以证明其配置合理性。

## 3) 3条可测试建议

1. **累计影子敞口断言**  
   增加测试：`sum(proposals.amount_usd) / balance_usd ≤ 0.8`。当前值为 `76.75%`，已逼近阈值。若未来新增影子提案，应确保累计分配后仍至少保留 `0.01 USD` 或等值缓冲。

2. **重复/阶梯记账检测**  
   对相同 `asset + compassion_check` 的 `executed=false` 提案，检测金额是否出现成对重复或单调递增。当前数据出现成对重复且无批次标识，建议增加 `batch_id` 或 `intent` 字段；若缺失则标记为异常。

3. **虚拟执行回执测试**  
   即使 `executed=false`，也应为每条影子提案生成模拟执行回执，包含预计执行费用、滑点、收益快照和最小可执行额。然后断言：若 `tx_hash=null`，则必须同时满足 `executed=false`，且 `balance_usd - sum(shadow amounts) ≥ 0`。当前第 8 条时间字段被截断，也需要补全后才能纳入完整时序校验。
