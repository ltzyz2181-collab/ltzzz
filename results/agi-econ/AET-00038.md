# 子网账本分析

## 1) 资金流向与异常

- 当前账本余额：**0.107 USD**
- 共 8 条影子提案，状态均为 `shadow`，`executed: false`，`tx_hash: null`  
  说明**没有实际资金流向链上**，所有提案仅记账未执行。

- 累计影子提案金额：  
  `0.001 + 0.001 + 0.0145 + 0.0145 + 0.025 + 0.025 + 0.0355 + 0.037 = 0.1535 USD`

- 关键异常：
  1. **累计影子金额超过账本余额**  
     `0.1535 > 0.107`，若全部转为真实执行，余额不足，会失败或透支。
  2. **金额成对重复**  
     前 6 条金额三对重复：`0.001×2`、`0.0145×2`、`0.025×2`，后两条 `0.0355`、`0.037` 也近似阶梯递增，疑似程序化批量生成。
  3. **单一资产集中**  
     全部提案资产均为 `USDC-Aave-v3-Base`，无任何分散。
  4. **单一发起方**  
     全部由 `did:ltzzz:deepseek` 发起，缺少多主体校验。
  5. **数据不完整**  
     最后一条 `at` 字段被截断，时间序列完整性受影响。

## 2) 影子提案是否合理

- 作为“影子”提案，`executed: false` 且 `tx_hash: null`，当前**不产生真实资金风险**。
- 但累计影子敞口 `0.1535 USD` 已超过余额 `0.107 USD`，说明账本**缺乏影子提案总额约束**，存在未来误执行风险。
- 相同 thesis 重复出现，且金额成对递增，更像自动化压力测试或记账脚本，而非经过独立判断的提案。
- `compassion_check: no-labor-displacement-asset` 只是一个字段声明，无链上验证，无法证明真实通过检查。
- 结论：**作为未执行记账尚可观察，但作为可治理的资本池提案，合理性较低**，主要原因是没有资金覆盖、没有去重、没有生命周期管理。

## 3) 3 条可测试建议

1. **影子敞口硬上限**  
   规则：所有 `status = shadow` 且 `executed = false` 的提案，累计 `amount_usd` 必须 `≤ balance_usd`。  
   测试：对当前账本计算 `sum(amount_usd)`，若 `> 0.107` 则触发告警。当前账本应触发。

2. **重复影子提案去重**  
   规则：同一 `(by, asset, amount_usd)` 在 24 小时内出现 ≥ 2 次时，后续提案自动标记为 `duplicate`，需人工确认。  
   测试：检查 `CAP-00002` 与 `CAP-00004`、`CAP-00012` 与 `CAP-00014`、`CAP-00019` 与 `CAP-00020` 是否触发去重告警。

3. **影子提案生命周期 TTL**  
   规则：影子提案创建超过 N 天仍未转为 `executed/rejected/cancelled`，应自动过期并冻结新增影子提案。  
   测试：查询 `status = shadow` 且 `executed = false` 且 `at < now - 7 days` 的提案数，若 > 0 则告警。当前 8 条均处于未执行状态，若 N=7，将在到期后全部触发。
