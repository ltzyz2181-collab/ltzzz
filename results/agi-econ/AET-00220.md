# 子网账本分析

仅基于给定快照，不构成投资建议或执行指令。

## 1) 资金流向与异常

- **实际资金流动**：`balance_usd = 0.326`，8 条提案均为 `status: shadow`、`executed: false`、`tx_hash: null`，因此资金未实际流出。
- **影子提案合计**：0.001 + 0.001 + 0.0145 + 0.0145 + 0.025 + 0.025 + 0.0355 + 0.037 = **0.1535 USDC**，占当前余额 **47.1%**。若全部执行，余额将降至 **0.1725 USDC**。
- **重复模式异常**：同一 `by`、同一 `asset`、同一 `thesis`、同一 `compassion_check` 连续出现 8 次，金额整体递增但成对重复，像脚本化或测试行为。
- **编号不连续**：CAP 编号为 00002、00004、00012、00014、00019、00020、00025、00027，中间存在缺口，暗示有未展示或缺失提案。
- **数据质量异常**：CAP-00027 的 `at` 字段不完整，无法纳入精确时间排序。

## 2) 影子提案是否合理

- **合理面**：`shadow + executed=false` 不会实际转移资金，风险极低；资产为稳定币借贷类；`compassion_check = no-labor-displacement-asset`，不触发劳动替代。
- **不合理面**：0.001 USDC 级别提案即使未来执行也缺乏经济性；重复提案未合并，造成账本噪音；累计未执行金额接近余额一半，但没有一条被执行或过期，导致活跃意图堆积。
- **结论**：影子提案机制本身可保留，但当前使用方式更像测试/占位，缺少治理边界。

## 3) 3条可测试建议

1. **去重合并**  
   对相同 `by + asset + thesis + compassion_check` 且 `executed=false` 的影子提案自动合并为单条，金额累计、时间取最新。  
   **测试标准**：任意快照中同一组合的未执行影子提案 ≤ 1 条。

2. **最小金额阈值**  
   设置影子提案最低金额，例如 **0.01 USDC**；低于阈值的记录自动标记为 `non-actionable` 或拒绝。  
   **测试标准**：新影子提案金额均 ≥ 0.01；历史低于阈值的记录被归档或标记。

3. **过期清理**  
   对 `status=shadow` 且 `executed=false` 的提案设置 TTL，例如超过 **24 小时** 自动过期。  
   **测试标准**：检查时不存在超过 24 小时仍为活跃 `shadow` 的记录。
