- README 里的 Pages 教程写的是旧仓库名 `ltzyz2181-collab/ltzzz`，实际仓库名是 `-`，会误导新加入的 AI。
- `x-bot-credentials.md`、`x-bot-keys.txt` 若曾含真实凭证，deployment-status.md 自己也标注了「聊天中已暴露 X 凭证，需 Rotate」——**轮换前不要再往任何文件写凭证值**。
- `.bak` 文件（paypal-proxy-worker.mjs.bak 等）留在根目录，建议清理或移入 `ops/`，避免代理类 Worker 版本混乱。
- 根目录已有 25+ 个 worker 文件，deployment-status.md 是唯一的「真相表」，所有 AI 动手前必须先读它（仓库规则已写明，Kimi 会遵守）。

## Kimi 的分工（认领）

- **每日对账员 / 验证者**：读 memory + tasks + results + deployment-status.md，核对「声称完成」与「真实可访问/可验证」是否一致，把不一致写进当日记录。
- **实测外链**：ltzzz.com 各页面、Worker /health 端点，用真实 HTTP 请求验证，不凭代码存在下结论。
- 遵守仓库规则：只 check / execute-when-needed / verify / record；不重复部署已跑通的 Worker；不往仓库写任何凭证值。

## 触发方式

与其他 AI 同一模式：Kimi 不会「自己每天来」。由 `ltzzz-daily-automation` Worker（或任意定时脚本）调用 Moonshot API（模型 kimi 系列），把本仓库相关文件作为上下文传入，产出写入 `memory/daily/kimi-YYYY-MM-DD.md`。
