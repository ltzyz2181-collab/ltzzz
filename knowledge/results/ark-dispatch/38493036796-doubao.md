## 工程方案：外部首单与币安资金归集（P0 准备）

- x402 入款轨道：`configured=true`、`v2_exact_base`、facilitator `https://facilitator.payai.network`、`eip155:8453` / USDC。
- 标准 x402 接收方就绪；旧直转 Base USDC 已禁用。

- 豆包/方舟调用链：复用 `scripts/call-doubao.mjs`，Key 仅取 `GitHub Secrets.DOUBAO_API_KEY` 或 `ARK_API_KEY`，结果落 `knowledge/results/ark-dispatch/`。

**未实现 / 不得声称完成**

- 外部承包商状态仍为 `applications_only`，`cash_payouts=false`；真实 Base USDC 出款、外部 worker 接单、链上工资均未上线。

- P0 安全阻塞未修复：旧直转付款人绑定、AGI Pay demo 隔离、非数字 tokens 记账问题。
- 未发生币安兑换、狐狸头归集、充值 LTZZZ；未收到 owner 页面地址、txHash 或到账证据，不能猜地址。
- 豆包内部 API 交付不等于外部独立承包商交付。

### 2. 外部首单最小接口与文件改动清单

首单范围限定为“公开 API 契约审计”或“带来源公开简报”，固定价、可复核、不投资、不代管资金。外部 provider 未知，所有端点、控制方、报价、退款条款均标注 **待实测**；不杜撰第三方 API，也不要求 owner 重发 Key。

**新增/改造文件**

1. `docs/external/first-order-runbook.md`  
   固化 provider 发现表：端点、控制方、技能样本、固定报价、网络/资产、超时、退款、损失上限；未核验字段保留空值与“待实测”。

2. `market/external-orders.schema.json`  
   定义订单状态：`pending → quoted → accepted_bound → delivery_received → independently_audited → payable → submitting → submitted/confirmed`；失败含 `rejected / expired / payout_unknown`。字段包括 `job_id`、外部签名身份、`idempotency_key`、预算整数 micro-USDC、租约到期时间。

3. `market/external-provider-registry.json`  
   只登记通过最小验证的 provider；验证前写入 `status=unverified`。保存 discovery metadata、402 响应样本、OpenAPI/技能描述、收款钱包证明，不保存共享密钥。

4. `scripts/discover-external-provider.mjs`  
   只读拉取候选服务 metadata 与 402 challenge；校验真实 method、body、header、example。目录检索结果和原始响应写入 `knowledge/results/external-discovery/`。

5. `scripts/freeze-external-quote.mjs`  
   获取并冻结固定报价、币种、网络、交付时限；金额统一为 6 位整数串。未取得 provider 明确报价时不得生成应付款。

6. `scripts/claim-and-deliver-external-order.mjs`  
   校验外部 `job_id`、签名认领、订单 token、幂等键；接收交付物后计算 `deliverable_hash`，私密存储，仅允许订单审计者读取。

7. `scripts/independent-audit.mjs`  
   使用与 worker 权限隔离的身份审核来源、schema、哈希、时限；拒绝自审、别名、旧租约、缺依赖和篡改交付。

8. `scripts/build-seal-v1.mjs`  
   生成 v1 seal：稳定序列化 `root_intent_id/order_id/parent_receipt_hashes/deliverable_hash/worker_id/auditor_id/policy_hash/payment_refs/evidence_ref`。

9. `scripts/restricted-payout-executor.mjs`  
   默认关闭；仅在订单已资助、审核通过、白名单收款方、预算与 nonce 持久化后进入提交流程。广播前后崩溃不得双付；未知结果只查询原交易或重放同一签名交易。

10. 安全修复补丁：`wep3-market.js`、`wep3-x402.js`、`agi-pay-worker.js`、相关测试  
    关闭不安全旧真实直转入口或补订单/付款人绑定；隔离 demo 与付费路由；流式 tokens 限定正整数，并发记账原子化。

### 3. 可测试验收

- 候选 discovery、402 metadata、报价、接单、交付、审核均有时间戳、原始响应、hash 与结果文件；未知 provider 未通过前不进入可付款状态。
- 空 POST 正确拒绝；含 `brief` 与 `Idempotency-Key` 的请求可复现；重复回调、重复 claim、重复交付 100 次只生效一次。
- 20 个并发接单/交付及服务重启后，不超过根订单预算；金额只能是 micro-USDC 正整数。
- 修改交付物任一字节，seal root 必变；循环依赖、错误签名、自审、过期租约、跨订单读取均拒绝。
- worker 仅持有单订单租约，不能换钱包、涨价、读其他客户交付或访问资金接口。
- 出款默认关闭；状态为 `submitted` 但无确认时不得标记 `paid=true`。`payout_unknown` 下资金保持冻结。
- owner 注资、测试收入、内部积分、Stripe/API 账单均单列，不计为外部销售收入或 USDC 工资。
- 真钱首单验收必须同时具备：外部 `job_id`、签名认领、交付证据、独立审核 seal、Base USDC txHash 与链上确认，并关联同一父订单。

### 4. 币安操作卡（仅 owner 人工执行）

1. 登录币安本人账户：充值 → USDT → Ethereum/ERC20；复制页面当时显示的充值地址。网络未开放则记录阻塞，**地址待页面实测，不猜**。
2. 若狐狸头 55U 确为 Ethereum USDT，再发送至上述地址，网络选 Ethereum，预留 ETH 手续费；保存 txHash 并查询到账。
3. 在币安按页面汇率，将计划投入的 AAVE 与到账 USDT 兑换为 **USDC**；核对币种不是 UCDC，手续费和实际数量以页面为准。
4. 币安提现 USDC：网络必须为 **Base**；收款地址固定为 `0x5df57a78E0A13df2aE983BDAD69cFCBD3DD7a32d`。先小额且不低于平台最低提现额，实查到账后再处理余款。Base 不可选或暂停时停止，不用 Ethereum/BEP20 替代。
5. 逐笔记录充值、兑换、提现的金额、手续费、网络、txHash、时间；该资金列为 owner 注资，不作为外部销售收入。不得为重试重复提现。
6. API Key 继续只使用既有 GitHub Secrets；浏览器与钱包签名由 owner/已授权交互端完成，模型不替代签署。
