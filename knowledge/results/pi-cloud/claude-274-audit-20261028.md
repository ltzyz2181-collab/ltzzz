## 发现
**R1（需改，可复现绕过）— 表达式正则被字符串内的 `}}` 截断。** `scanWorkflowSecretReferences` 用 `/\$\{\{([\s\S]*?)\}\}/g`，遇到字符串字面量里的 `}}` 就提前结束，后面的 `secrets.X` 不再被扫描。已复现（均 **未检出**）：
- `K: ${{ format('}}') && secrets.OWNER_PK }}`
- `K: ${{ '}}' && secrets.FUNDING_EXECUTOR_KEY }}`
这正好绕过“动态/整个 secrets 集合”覆盖的声明。建议：不要用正则切表达式；改为对整个文件再做一次不依赖 `${{` 边界的兜底——任何出现 `\bsecrets\b`（忽略注释之外）且不属于“已解析的白名单名字”的位置一律报错；或实现带字符串字面量感知的扫描。

**R2（需改）— `secrets: inherit` 未覆盖。** 调用可复用 workflow（含外部仓库 `uses: owner/repo/...@ref`）时写 `secrets: inherit`，没有 `${{ }}`，扫描器检出 0 项。已复现。外部可复用 workflow 可以读取全部 Secret。建议：任何 `secrets:\s*inherit` 报错，`uses:` 指向仓外 workflow 一律报错或单独白名单。

**R3（设计缺口）— 用“黑名单名字正则”而不是“白名单名字”。** 非敏感名字只记为 `nonfinancial_credential_reference`，且**永不产生错误**。已复现以下名字均被当作无害通过：`WALLET_MNEMONIC`、`SEED_PHRASE`、`SIGNER_KEY`、`RELAYER_KEY`、`DEPLOY_KEY`、`HOT_WALLET`、`KEYSTORE_JSON`、`PRIVKEY`、`ETH_PRIV`、`PK_ETH`。另：`OKX_API_KEY/OKX_API_SECRET/OKX_API_PASSPHRASE` 在测试里被明确当作“无害”，现仍传入 `verify-kimi-okx.yml`；若该交易所 API 带交易/提现权限，则是财务凭据（代码层有旧出口守卫，但 workflow 层应登记权限仅读取）。建议：改为白名单——已登记名字+用途（模型 API、Cloudflare 部署令牌等）才可引用，其余一律报错；OKX 凭据需登记“仅读权限”的证据位。

**R4（未验证/说明）— 该守卫是检测，不是栅栏。** `small-payment-policy.yml` 在 `pull_request` 上运行的是 PR 自带版本的守卫源码，PR 可同时改守卫；`push` 触发的 paths 只含两个 workflow 文件而非 `.github/workflows/**`。注释中的“protected guard source”只有在 base 分支必需检查/代码所有者保护下才成立，本审计**未验证**分支保护或 ruleset。建议：必需检查改用 base 分支（`pull_request_target` + 可信 checkout，或固定哈希）运行，并把 `.github/workflows/**` 加入 paths。

**R5（提示）** 注释行里的 `${{ secrets.X }}` 也会被报错（偏保守，可接受）。多行表达式、大小写混用、`secrets . X`、`secrets['X']`、`toJSON(secrets)`、`secrets[env.N]`、`fromJSON(toJSON(secrets))` 均已验证被检出。复合 action（`.github/actions`）不在扫描范围，但复合 action 无法直接读 secrets 上下文，只能经 workflow 传入，故由 workflow 扫描覆盖。
