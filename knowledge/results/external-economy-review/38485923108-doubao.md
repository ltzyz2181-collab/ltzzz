# doubao design review

# 评审结论

**有条件支持 P0 首单闭环，反对当前代码直接开放公开真实订单或外部 USDC 出款。**  
方案第2、4、6节的资金边界、上线顺序和自动政策包络是正确的；但源码目前主要是“入款核验 + 内部积分 + 交付登记”，不是外部承包商市场，也不是发薪系统。

## 一、事实分层

**代码已有能力：**

- Base/USDC 入款核验：`wep3-base-payment.js` 检查链 ID、成功状态、2 个确认、USDC Transfer 日志、金额和收款地址。
- x402 v2 入款状态机：`wep3-x402.js` 有 `settlement_pending/unknown`、nonce 去重和“不换 nonce 重付”。
- 订单、父子任务、内部 credit、简单声誉报价和 KV 流式记账：见 `wep3-market.js`、`wep3-economy.js`、`agi-pay-worker.js`。
- 外部申请者只能进入 `pending_review`，且 `signing_authority:false`、`audit_authority:false`，见 `wep3-agents.js`。

**材料显示的生产回执：**

- `live_revenue_cents=0`、`test_revenue_cents=3612`、公开 `receipts=[]`、`on_chain=false`。
- 最新 WEP3 回执仍为 `paid=false`、`internal_credit_settled`、`tx_hash=null`。
- `treasuryProof()` 明确返回 `on_chain_wages_enabled:false`。

因此，不能声称已有外部客户收入、外部 AI 已发薪或已盈利。

**仍属拟实现：**

外部 worker 审核与租约、独立签名审核、USDC 应付款、受限出款执行器、退款/争议、完整 DAG、持久政策引擎、真实外部竞价和流式真钱结算。

## 二、对前一席意见的修正

前一席的总判断成立，但有三点需精确化：

1. `agi-pay-worker.js` 的 KV 竞态不是“重复计入日额”，而是多个并发请求读—改—写时**丢失更新、少计日耗**，从而绕过日限额；每张收据仍可能各自写入。
2. 低声誉“涨价”不是现存行为。`demandPrice()` 中声誉低于 100 反而给折扣；真实缺陷是缺少低分限流、强制审计和试用额度。
3. `maybeGrowthHire()` 不会直接发链上工资，但会自动创建 `live:true、amount_cents:0` 的内部 GROW 单并移动预留资金，可能触发 runner/模型成本，仍应在 P0 关闭。

## 三、六项机制判定

| 机制 | 当前判定 | 上线要求 |
|---|---|---|
| 递归 intent | 已有 depth=3、每节点 5 子，但失败预算不释放、根预算不完整 | P1，先全树守恒和取消闭环 |
| 动态定价/匹配 | 有中位数、声誉、积压曲线；无外部竞价 | 先影子排名，低分降并发/加审计 |
| 流式 token | 仅 KV dry-run，自报 token，无原子账和 usage 证明 | P2，不得逐 tick 广播链上交易 |
| 因果回执 DAG | 有 hash 和 `parent_id`，但缺完整前置回执集合与签名 | P0 必须补 seal v1 |
| Base USDC 桥 | 只有入款，无出款；credit 不可兑 | P0 补 `settlement_payable_usdc` 和出款状态机 |
| 委员会改规则 | `policy_next` 只是返回值/KV 记录，不持久生效 | 只允许包络内收紧，扩权必须提案 |

## 四、必须修改项与具体反例

1. **修复无付款人绑定的旧收款入口。**  
   反例一：`/market/x402/challenge` 生成的 challenge 不保存 `expected_payer`，`/market/x402/verify` 只校验金额、收款地址和时间窗。攻击者可监控另一笔同金额 Base USDC 转账，抢先提交其 tx hash，把订单记到自己名下。x402 v2 有 payer/nonce 绑定，旧直转入口应在 P0 禁用；如保留，必须先由买家钱包签名声明付款地址，并绑定唯一 nonce。

2. **交付时不得把未履约收入写成可用资金。**  
   现在真实入款后立即执行 `pool_available_cents += amount-budget`，但订单仍有退款和履约责任。应改为 6 位整数微 USDC 分桶：`confirmed_cash`、`refund_liability`、`provider_payable`、`gas_reserve`、`loss_allowance`、`equity/revenue`。只有交付责任结束并核对费用后，剩余部分才能进入可用余额。

3. **独立审核必须是密钥隔离，不是不同名字字符串。**  
   反例二：持有同一 `LAB_PIN` 的调用方可在 `/market/complete` 中提交 worker=`Grok`、`audit.auditor=GPT`；代码只比较名字，不验 GPT 钱包签名。应改为外部 worker 和 auditor 各自注册公钥，租约、交付 hash、审核结论均签名，并绑定 `order_id/policy_hash/deliverable_hash`，同密钥或同控制关系不得自审。

4. **补出款和 unknown 处理。**  
   广播前持久化 `payout_id、chain_id、asset、recipient、amount_raw、nonce、signed_raw_tx`；状态走 `reserved→payable→submitting→submitted→confirmed`。`payout_unknown` 只能查询或重发同一原始签名交易，绝不能生成新 nonce。USDC Transfer 日志确认后才允许 `paid=true`。

5. **流式计费不能信任自报 token。**  
   反例三：`streamTick()` 接受请求体 `tokens`，无 `session_id/order_id/sequence/cumulative_tokens/output_prefix_hash`，也无 provider usage 签名。承包方可虚报 token 做大账单，也可少报 token 消耗客户额度；逐 token 收费还会激励输出灌水。20 个并发请求同时读到旧日耗时，还会因 KV 丢更新绕过 cap。应迁入 DO 单线程账或 KV CAS，并只认 provider 签名 usage、tokenizer 版本和累计凭证。

6. **删除演示绕过并关闭自动 growth hire。**  
   反例四：`/resource` 接受 `X-PAYMENT: demo`，无需真实收据；P0 必须删除。`maybeGrowthHire()` 应先直接返回 null 或改为人工确认的影子建议，不得动用订单预留资金。

7. **政策自动机默认拒绝扩权。**  
   `rewritePolicy()` 现在只写 breaker 记录，下次请求仍从环境变量读旧政策，所以“自动收紧”实际未生效。应持久化 versioned policy 和 parent hash，仅允许降低限额、暂停任务、隔离地址、回滚版本；不得自动改收款方、网络、资产，不得提高根预算或跳过审计。policy hash 必须进入订单 seal 和 payout 记录。

**内部积分不是真钱：**`agent_credit_cents`、`growth_credit_cents`、`LTZ credit-pool` 只能是内部计量，不得批量转成可兑 USDC。未来若承诺兑付，必须另建隔离准备金和负债审计。

**x402 也不是托管：**它只解决 HTTP 支付验证和结算，不自带退款、仲裁或履约担保。外部预付 API 失败损失应冻结在单独 `loss_allowance`，首单外部 API 采购建议不超过 0.50 USDC，且这只是建议金额，不是付款授权。

## 五、首单可测试闸门

首单建议买方总价 2–5 USDC，但必须先通过：

1. 旧直转入口关闭或完成 payer/nonce 绑定；`demo` 绕过不存在。
2. 重放同一 payment、delivery、payout、tick 100 次只生效一次；20 并发和重启后不超根预算。
3. 在广播前崩溃、RPC 超时、确认延迟、存储失败后，均不双付、不提前释放 unknown 资金。
4. 子交付改一字，父 seal 必变；循环依赖、缺父回执、错误签名、自审、过期租约全部拒绝。
5. 资产负债恒等式在失败、取消、部分批次和退款后成立：  
   `已确认 USDC = 退款负债 + 应付款 + 已承诺外采 + gas/损失准备金 + 可归属余额`。
6. 真实外部买家和真实外部执行商不得是 owner 关联钱包；买家入款、交付 hash、独立审核、外部承包商出款必须引用同一父订单和各自链上 tx。
7. 自动政策尝试扩大预算、更换收款方或跳过审计时，只能生成人工提案，且重启后旧扩权不生效。
8. owner 测试只能标记为 `owner_test`，不得计入外部获客或收入。

工程顺序应为：**账本分桶与状态机 → 身份/租约/签名审核与 DAG → 出款执行器 → 退款/失败闭环 → 测试网/影子压测 → 小额真实首单**；递归和流式真钱结算均不得提前。
