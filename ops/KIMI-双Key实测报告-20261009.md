## 二、国内 Kimi（MOONSHOT_API_KEY_CN）—— 🟢 完全可用

### 2.1 实测证据

```
端点   ：https://api.moonshot.cn/v1/chat/completions
模型   ：kimi-k2.6        ← 重要：旧模型名 moonshot-v1-8k / kimi-k2-0711-preview 已废弃
验证   ：GET /v1/models         → HTTP 200，列出 kimi-k2.6 / kimi-k2.7-code 等
余额   ：GET /v1/users/me/balance → HTTP 200
         {"available_balance": 14.0963, "voucher_balance": 14.0963, "cash_balance": 0}
实调   ：POST /v1/chat/completions
         请求 : {"model":"kimi-k2.6","messages":[{"role":"user","content":"回复：KIMI-CN-OK"}],"max_tokens":300}
         响应 : 回复内容 = "KIMI-CN-OK"｜finish_reason = "stop"
         用量 : prompt 15 + completion 223 = 238 tokens（其中 reasoning 215）
         模型 : kimi-k2.6
```

**证毕：不是"has_key:true 但 POST 失败"，而是真实返回了内容。**

### 2.2 两个关键发现（其他 AI 必须知道，否则会误判）

> ⚠️ **发现 1：模型名已换代。**
> 旧文档/脚本里写的 `moonshot-v1-8k` 现在**返回 404**（`Not found the model ... or Permission denied`）。
> **这不是 key 坏了，是模型名废弃了。** 正确用法：**`kimi-k2.6`**。
> 本仓 `key-liveness.yml` 曾在用 `moonshot-v1-8k` 探测——会误报 key 失效，**已一并修**（见探针修正）。

> ⚠️ **发现 2：kimi-k2.6 是推理模型。**
> 它的 `completion_tokens` 里绝大部分是 `reasoning_tokens`。
> 若 `max_tokens` 设得太小（如 5），**内容字段会是空字符串**（token 全被推理吃掉）——
> 这会被误判为"调用失败"，实际是**成功且已计费**。**探针必须给足 max_tokens（≥200）。**

### 2.3 计费观察

- 调用前后余额均为 `¥14.0963`：消耗走的是**赠金（voucher_balance）**，尚未动用现金。
- 每轮 238 tokens 的成本极低，**¥14 够跑很久**（按 kimi-k2.6 常规价格估算，约可支撑数千次短对话）。

## 三、国外 Kimi（MOONSHOT_API_KEY）—— 🔴 key 有效但账户停用

### 3.1 实测证据

```
端点   ：https://api.moonshot.ai/v1/chat/completions
验证   ：GET /v1/models → HTTP 200，正常返回模型列表
         （说明 key 本身合法、未过期、未吊销）
余额   ：GET /v1/users/me/balance → HTTP 200
         {"available_balance": 0, "voucher_balance": 0, "cash_balance": 0}
实调   ：POST /v1/chat/completions → **HTTP 429**
         错误 : "Your account org-799c4b4226894783b942091cc105371f
                <ak-fcziwg9xgmsi11fpycw1> is suspended due to insufficient balance,
                please recharge your account or check your plan and billing details"
         类型 : exceeded_current_quota_error
```

### 3.2 判定

**这是"余额问题"，不是"key 问题"。** 区别很重要：
- ✅ key 有效（能列模型）
- 🔴 账户被停用（余额 $0）
- 🔴 **任何调用都会 429**

### 3.3 与旧记录的关系（勘误）

| 旧记录 | 实际 |
|---|---|
| 「境外 Kimi 已在 ltzzz-kimi-proxy 配好，当前 429 限流（key 有效、额度受限）」 | ✅ 方向对，但**原因说错了**：不是"限流（rate limit）"，是**账户欠费被 suspend** |
| — | 更正：`429 exceeded_current_quota_error` = **余额不足**，非 RPM 限流 |

**跨端点交叉验证**：国内 key 打国外端点 → **HTTP 401 Invalid Authentication**
→ 证明**两把 key 不通用**，各自绑定各自端点，不可互换。

## 四、给其他 AI 的使用说明（照抄即可）

### 4.1 谁该用哪把

| 席位 | 该用 | 状态 |
|---|---|---|
| **国内 Kimi**（中文记忆校对/日期引用核查）| `MOONSHOT_API_KEY_CN` → `api.moonshot.cn` | 🟢 **现在就能干** |
| **国际 Kimi**（英文研究/海外订单）| `MOONSHOT_API_KEY` → `api.moonshot.ai` | 🔴 **先执行已部署的无 Key 文件任务；确有 API 任务再充值** |

### 4.2 正确调用格式（国内）

```bash
curl -X POST https://api.moonshot.cn/v1/chat/completions \
  -H "Authorization: Bearer $MOONSHOT_API_KEY_CN" \
  -H "Content-Type: application/json" \
  -d '{"model":"kimi-k2.6","messages":[{"role":"user","content":"..."}],"max_tokens":1000}'
```

**三条铁律：**
1. **模型名用 `kimi-k2.6`**（不要用 `moonshot-v1-8k`，已 404）
2. **max_tokens ≥ 200**（推理模型，给少了内容为空）
3. **key 不进对话、不进仓库、不进回执**（只经 Secret 注入）

### 4.3 国际 Kimi 的无 Key 替代路径

国际 Kimi 席位**不必空等充值**：
- 已有的 `kimi-global-weekly.yml` 工作流**本就不依赖 Moonshot API**（它用 xAI/Grok 引擎，见其 step 名 `no Moonshot API`）
- 所以「国际 Kimi 英文研究、海外订单与雇佣提案」→ **先跑这条已部署的无 Key 路径**
- 只有"确需 Moonshot 官方 API"的任务，才触发充值决策
