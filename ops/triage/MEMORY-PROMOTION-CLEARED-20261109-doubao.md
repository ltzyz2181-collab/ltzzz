## 1｜口径调整（owner 指令 → 代码）

owner 指令："通过还是不通过写出原因，不影响的原因还是要通过，不然以后还阻塞。"

据此把 `reviewerPrompt()` 的判定从"择优/严格"改为**两级标准**，已进 main 并长期生效：

**只有这四类才判不通过（影响使用）：**
- A 事实错误，或与已载事实直接冲突
- B 把未验证的推断写成已证实的事实
- **C 来源伪造、无法追溯**
- D 涉及资金/权限/安全的错误结论

**这五类一律通过，只写限制，不得据此拒绝：**
- 表述不够精炼、粒度偏粗或偏细
- 部分内容是对已有记载的复述，但主体含可复用事实
- 含少量过程字段（时间戳、run_id、http 状态码）
- 属阶段性状态（后续可能变），但当前确为一致记录
- 覆盖面不全

并明确要求：**部分内容有问题不影响整体通过**，只要整条整体仍可安全复用。
