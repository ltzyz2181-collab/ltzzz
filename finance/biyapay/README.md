# LTZZZ × BiyaPay 境外 AI 自主运营支付系统（调查 + 架构设计）

> 状态：**调查与设计阶段** —— 按用户要求，确认官方能力前不部署真实支付。
> 调查时间：2026-09-16
> 关联：支付宝 400 元账本（境内）与 BiyaPay U 卡（境外）**分账管理，不混账**。

---

## 一、调查结论（截至 2026-09-16）

### 1. BiyaPay 是什么

- BiyaPay（biyapay.com / biyagl.com）是**全球资产兑换与汇款工具 + 虚拟卡（速捷卡 EasyCard）**平台，App 为主。
- 合规主体：Biya Global LLC（美国 SEC 注册，编号 802-127417；FINRA 会员 CRD 325027）。
- 速捷卡 = **Visa/Mastercard 虚拟预付卡**，USD 计价；覆盖 190+ 国家/地区；适用于 ChatGPT、Claude 等 AI 订阅。
- 费用：开卡费 $2、充值费 1.8%、退款费 2%、交易费 $0.5/笔。
- **限制中国内地使用**；禁止恶意退款/纯验证消费（会被冻结卡甚至封号）。

### 2. 官方 API / 自动化能力核查

| 用户需求能力 | 官方现状（已核查） | 结论 |
|---|---|---|
| 开发者文档 / 开放平台 | 官网、帮助中心均**无开发者/API 栏目**；无开放平台、无 SDK、无沙箱 | ❌ 无公开文档 |
| API Key / 密钥自助申请 | 无自助申请入口 | ❌ 需联系官方 |
| 账户信息 API | 无公开接口（App 内查看） | ❌ |
| 卡片状态 / 余额 API | 无公开接口（App「资产-虚拟卡」查看） | ❌ |
| 交易查询 / 历史 API | 无公开接口（App 内账单；帮助中心明确**不支持账单下载**） | ❌ |
| 自动支付 API（程序化扣款） | **无**。速捷卡是卡组织虚拟卡，扣款由**商户端发起**（订阅/消费时输入卡号），BiyaPay 侧不提供持卡人程序化支付接口 | ❌ |
| 退款 / 对账 API | 无公开接口（退款走 App 或卡组织争议流程；有 2% 退款费） | ❌ |
| Webhook / 余额变化通知 | 未公开 | ❌ |
| 博客所称 "open API" | 仅营销文案提及"多链互操作/自动化资金流"，**无文档、无链接、无 SDK 支撑** | ⚠️ 无法验证，视为未开放 |

> **关键结论**：截至调查日，**BiyaPay 官方没有可被 AI 程序化调用的自动化支付/查询 API**。
> 按用户红线「官方没有自动化能力，不能通过破解/绕过实现自动支付」→ **现阶段不得实现"AI 调 API 自动付款"**。

### 3. 可用的合规路径（不绕过任何安全机制）

1. **商户订阅绑定（半自动，合规）**：AI 决策 → 用户/授权人把 LTZZZ 速捷卡**一次性绑定**到目标商户（Claude / OpenAI / GitHub / Cloudflare 等，卡号 CVV 只在官方支付页录入）→ 后续由**商户订阅自动扣款** → 交易记录进 App 账单 → 人工/授权同步进 LTZZZ 账本。这符合"AI 判断 → 自动扣款（订阅）→ 记录"，且完全不绕过风控/3DS。
2. **联系 BiyaPay 官方申请企业/机构 API**：若官方有面向企业的开放通道（邮件 service@biyapay.com / Telegram @biyapay001），**由用户本人申请**，拿到官方 API 文档与密钥后再做程序化集成。
3. **人工同步对账**（过渡）：AI 记录决策与预期支出 → 用户每月/每周从 App 导出/截图账单 → AI 比对写入账本 → 复盘。

## 二、系统架构设计（按用户 16 点要求）

### 1. 账户归属与资金隔离

| 资金池 | 渠道 | 用途 | 记账 |
|---|---|---|---|
| 支付宝 400 元（境内） | ltzzz-pay-proxy | 境内数字服务（已建成） | `ltzzz:balance`（支付宝账本） |
| BiyaPay U 卡 ≈ 10 USDT（境外） | 本设计 | 境外数字服务（Claude/OpenAI/GitHub/Cloudflare/AI API/VPS/域名等） | `biyapay:` 账本（KV/文件） |

- 用户个人卡（香港大象银行、工行留学生卡）**不进入本系统**。
- 两个账本独立初始化、独立统计、独立停止条件，**不混账**。

### 2. AI 授权边界

- 授权范围：仅 LTZZZ 项目相关的境外数字服务（见用户清单 16 项）。
- 决策权：AI 自主判断"是否花/花多少/买什么/何时花"，**不逐笔询问**。
- 资金上限：**当前卡内余额（约 10 USDT）为硬上限**；不得扩大资金来源（不新增卡、不充值外部来源、不借款）。
- 敏感操作仍由用户执行：绑定卡、API 密钥申请、首次授权。

### 3. 自动化流程（目标态）

```
GPT 总控 → LTZZZ 任务队列 → 豆包（执行）→ 判断需要境外服务？
   ├─ 否 → 继续原任务
   └─ 是 → 读取 BiyaPay 余额（人工同步/未来官方 API）
          → 校验：属于 LTZZZ + 金额 ≤ 余额 + 服务在允许清单
          → 创建支付任务（记账：服务/金额/原因/预期）
          → 支付：① 官方 API（待官方开放）② 订阅自动扣款（卡已绑定）③ 人工执行（过渡）
          → 记录交易结果（成功/失败/交易号/余额）
          → 写 LTZZZ 账本 + AI 决策日志
          → 继续原任务 → 实验结果 → GitHub 知识库
```

### 4. 账本（LTZZZ AI 运营账本 · BiyaPay 分账本）

记录字段（每笔必填，缺记录视为违规）：
- 时间、AI（豆包/GPT/总控）、支付对象（商户）、服务/商品、金额（USD）、支付原因、预期用途
- 支付结果（成功/失败）、交易编号、支付后余额
- 后续评价（继续/停止/观察）、复盘结论

### 5. ROI 复盘（花钱不是终点）

每笔支付后自动生成实验记录：
- 为什么花 → 实际用多少 → 产出什么（条数/可用数）→ 是否提升产能 → 是否续费 → 结论+原因
- 形成：资金 → AI 决策 → 采购 → 使用 → 结果 → 复盘

### 6. 安全与敏感信息

- 卡号/CVV/有效期/PIN/2FA/支付密码**绝不入** GitHub/前端/JS/日志/聊天/视频/提交记录。
- 若未来官方 API 提供密钥 → 只放 Cloudflare Secret / 环境变量 / Vault。
- 人工录入只允许出现在**官方支付页面**。
- 禁止：绕过验证码/3DS/支付密码/风控/账户限制、破解签名、伪造支付结果、改请求绕权限、窃取 Cookie/Session。
- 账单地址：用户指定的 San Jose 地址**仅在 BiyaPay 官方登记的账单地址一致时**使用；不一致以官方记录为准，不虚构。

### 7. 失败处理（防重复扣款）

- 支付失败：不无限重试；记录 失败原因/商户/金额/时间/API 返回。
- 决策：换支付方式 / 停止 / 等待 / 人工检查。
- 连续失败 N 次 → 自动暂停该商户（参考支付宝熔断机制，可复用 ltzzz-pay-proxy 的 fail-counter 模式）。

### 8. 测试顺序（第一阶段，dry-run 优先）

1. BiyaPay 账户连接/接口能力确认（官方 API 是否存在、用户账户是否有开发者权限）
2. 余额读取（App 人工确认 or 官方接口）
3. 交易读取（App 账单 or 官方接口）
4. 小额境外数字服务支付（订阅绑定，如 Claude $1 级验证）
5. Claude
6. GitHub / Cloudflare
7. 自动记录交易（账本）
8. AI 自主决定下一笔合理支出

每步完成后记录状态；真实支出前用户确认授权边界。

## 三、当前缺什么（不阻塞设计，阻塞真实支付）

| 缺口 | 谁解决 | 说明 |
|---|---|---|
| BiyaPay 官方 API（如有） | **用户联系官方申请**（service@biyapay.com / Telegram @biyapay001） | 询问是否有企业/开发者开放 API、API Key、沙箱；拿到文档才能程序化集成 |
| 账户开发者权限确认 | 用户在 BiyaPay App 内确认是否有「开发者/API」入口 | 若有 → 截图给我；若无 → 走订阅绑定模式 |
| 速捷卡绑定授权 | 用户/授权人在商户官方页绑定（一次性） | 卡号 CVV 只在官方支付页录入 |
| 账单导出/同步 | 用户定期提供 App 账单截图/导出 | 官方暂不支持账单下载，需人工同步过渡 |
| 余额初始值确认 | 用户确认当前卡内 USDT/USD 余额 | 账本以官方显示为准，不猜测 |
